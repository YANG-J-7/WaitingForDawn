`sites.json`描述三个固定样点：凸岩较强、小湾较缓、碎石岸较低；4/6/4秒周期和不同相位，全体12秒回环。anchor是水侧碰撞根点，size只在配置时确定，不随动作改变；water_floor是逐样点人工核对的水侧裁切平面，阻止水花穿入后方石头。该平面仅适配当前三样点，不是通用碰撞系统。

预览入口`res://tools/preview_lake_shore.tscn`，第二阶段为拍岸水花；暂停/复位控制所有水花。原有草地、石头与水面规则保持，原画不参与特效变形。实际60fps预览与GL证据保留本机`tests/reports/images/lake-shore-runtime/`。

当前为一套动作在三处按尺寸/强度/节奏复用，尚无三个独立形态变体。最终亮度、贴合及节奏待视觉复核；正式全岸布点、性能与4K验证待后续。

## 60fps水花（2026-11-13追加）

`playback-60fps.json`明确60fps采样：凸岩2.25秒135帧、小湾2.7秒162帧、碎石岸2.1秒126帧，合计423张透明插值帧。每帧512×256、锚点仍为(256,190)。来源仍是六张生成关键帧，新增中间帧为确定性预乘颜色插值，不是423张独立原画，也没有新增形态变体。

运行材质读取该契约的帧率，按`floor(实际局部秒数×60)`选择采样时刻，直接从原尺寸六关键帧求相同过渡；保持小图集显存占用，避免常驻423张PNG。按实际时间跳到对应采样，不因卡帧把整段动作放慢。固定根点、4/6/4秒周期和强度参数保持。动作片段之后需保留105/198/114帧透明休止，再开始下一次浪；不要将单独动作PNG直接首尾硬接。

使用Python运行`export_60fps.py --output <逐帧输出目录>`导出透明序列和同级`shore-splash-60fps.zip`。不传output只重建轻量契约。逐帧包含淡入消散和亮度，不含岸石、水侧裁切或样点强度；接入其他播放器时保留透明休止及固定锚点。导出器仅处理已有生成图。GIF无法准确表达60fps，60fps特写使用MP4。
