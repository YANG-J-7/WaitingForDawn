# 月湖山谷 3D 地图美术开发方案

2026-11-09 · 评审草案 · 适用于《Waiting for Dawn》第一关 `level_001` 的 P3 美术迭代。

**把图 3 做成一座冷月照亮的立体山湖沙盘。左侧平原留给建城，右上厚岩草台靠石梯串起，深蓝湖沿右侧山脚展开。主城火盆把视线拉回玩家的聚落。**

[参考图与转译依据](../../specs/waiting-for-dawn/research.md) · [现行美术圣经](art-bible.md) · [3D 技术方案](../../docs/architecture/moonlake-3d-map-and-lighting-development.md) · [Story-039](../../production/stories/story-039-moonlake-3d-level.md)

按 V5 落地的任务顺序、镜头对齐标准和关卡边界见[还原开发计划](moonlake-v5-reconstruction-plan.md)。

## 1. 视觉方向与设计测试

推荐 **手绘卡通 3D 山湖沙盘**。图 1 的宽倒角、大块分色和清楚剪影用于崖石、树和主城。图 2 的可读性落实到建筑高宽比、地基与入口，以及道路和空地之间的层次。图 3 决定地形构图、冷夜氛围与可建平原的留白。画面从大到小先读到山湖，再读到道路、地块和建筑，最后才看到草叶与石纹。

| 方向 | 收益与代价 |
| --- | --- |
| 手绘卡通 3D 山湖沙盘（推荐） | 轮廓和高差最容易看清。要求统一倒角、地形分材质和贴地标准，可以在现有 P3 上迭代。 |
| 更贴近图 3 的细密岩草 | 近景更有原图的丰富感。需要更多纹理变体和远景降噪，草地容易抢走单位与建造格的对比。只在崖脚和湖湾试用。 |

设计测试采用 1080p 同镜头截图。总览看两秒能分出平原、山台与水域，建设档看两秒能指出主城、可建空地与石梯入口。把建设档截图转灰度后，仍应区分平地、崖壁和水域，并识别可建与禁建预览。视觉结论以实机图和短操作回放复核。

## 2. 光照、情绪与时间

| 游戏状态 | 画面设计 |
| --- | --- |
| 开局与常态夜间 | 方向光照亮崖唇和台阶迎光面，冷灰蓝环境光托住背阴。草地留灰绿，湖面亮点限在近岸和少量水纹。主城延用门前双火盆作为暖色锚点。 |
| 战斗与拖牌 | 场景底色保持稳定。威胁由轮廓、方向提示与短促反馈表现。落点覆盖层单独提亮，树影和湖面高光避开关键提示。 |
| 最后 5 分钟 | 按有效对局时间逐步抬亮环境光，崖顶、屋脊和石阶朝暖灰过渡，水面保留冷蓝。取 00:00、30:00、55:00、60:00 四个已用时间点对照。 |
| 暂停与重开 | 水纹、树梢与火盆随表现时间冻结和续播，重开复位。天气预留为表现接口，具体类型、强度和玩法影响待相应设计确认。 |

先对照 P3 环境影与简化阴影档。默认候选是一盏方向光加环境光，投影重点为崖与树，主城两处短程暖灯关闭局部投影。密林影压住山路时，先削减密集投影或减弱阴影对比。湖面用深浅色带与滚动法线表现，避开对屏幕空间反射、体积雾和屏幕空间环境遮蔽的依赖。 [Godot 渲染器能力表](https://docs.godotengine.org/en/stable/tutorials/rendering/renderers.html#environment-and-post-processing)

## 3. 形状与区域制作

图 3 的位置关系用于审美对照。实际组装以现有 196×80 格和关卡坐标为准，主城、四林两石两铁、四处出生点、八条石梯和 S6 中转平台继续使用原数据。

| 区域或对象 | 造型与制作要求 |
| --- | --- |
| 平原与主城地面 | 先用共享草材质铺出连续草地，低频明暗决定开阔度。碎石和草簇集中在外缘、崖脚、岸边。建造腹地保留连续净面。主城地台延用已有候选，石基厚、屋顶分大面，门前空地和暖火引导视线。地基过渡以局部材质混合接草地。 |
| 山台、崖壁与坡脚 | 从草台、断续崖唇、蓝灰竖岩和坡脚四层起形。长崖优先分成粗宽岩柱和几处断点，用不等宽倒角体现体积。细裂纹进入材质。直段、内角、外角和端头共享石材，转角避免断纹和接缝。岩脚碎石集中在禁建边缘，保持通路轮廓。 |
| 石梯与山路 | 保留 P3 每级 5.6 的表现高差及 S6 中转平台 2.8 作为样区基线。实际踏面、坡脚入口、平台出口三个位置都要清楚。踏面用较亮灰褐，立面稍暗，入口两侧留净。石阶与接路压实成一条连续路径，装饰岩缝与土纹避开假岔路。 |
| 湖岸 | 从草缘、湿土和岸石过渡到浅蓝绿，再过渡到深湖蓝。主岸线由水域约束，湖湾以少量大岸石固定形状，碎浪只沿水缘断续出现。内收后的露边用湿石、深色碎砾表现，避免形成看似可建的平坦陆地。 |
| 林带与资源点 | 复用当前 Blender 针叶树，树冠成不等高的厚枝簇，外围成片、路口成疏边。树根按同一高度场贴地。资源林沿用独立资源 ID、入口与占用显隐，选中时显示资源符号。矿点先校准脚座和现有入口，石矿以宽钝岩块辨认，铁矿用细长矿脉剪影及独立图标辅助区分。 |
| 建筑与单位 | 主城用宽石基和厚屋脊，生产建筑低宽并露出作业入口，箭塔高窄。农民用竖直头肩和工具，守卫以较宽肩线和武器区分，狼以前倾、低长身段辨认。外部剪影和脚点优先于近景纹理。 |

## 5. 角色与环境动画

先用现有农民、守卫、狼和 3D 主城验证尺度。现阶段农民、守卫、狼仍以脚点对齐的 2D 立绘进入 3D 场景。S6 的验证重点是农民上下行时鞋底与踏面连续贴合，林缘重点是主体、标记及移动方向能从背景分离。未来若更换近景角色，先做农民走路、携货和交付三段，原点在脚底，按现有速度匹配步频。

树根静止，枝梢用小幅异相摆动。湖面两层纹理缓慢滚动，碎浪压在水域一侧。火盆以小幅亮度变化和少量火星提示活力。远景先移除草簇、裂纹高光和零碎火星，保留地形与资源轮廓。密林中优先压低或疏开遮住主要通道的树冠。仍挡住当前目标时，再测试只对相关树冠做局部淡化，拖放结束恢复。

## 6. 3D 落地与镜头

采用 **3D 环境与主城 + 2D 玩法网格 + 2D HUD**。从现有 [P3 预览](../../tools/preview_moonlake_3d_level.tscn) 开始，以关卡原点为基准，36 个二维世界单位对应 1 个 3D 水平单位。高度场为脚点、踏面和拾取提供共同基准。崖面装饰向禁走区内切，水纹限制在水域，拖放以第一个地表命中和完整占地为准。凡造型调整露出可见地块与落点差异，先在边界叠加视图中复核，再调整表现轮廓。

| 镜头 | 画面要求 |
| --- | --- |
| 总览 | 使用现有俯视全图，第一眼呈现平原、山台和湖岸。主城、资源、威胁入口使用独立标记。 |
| 布防、建设 | V5 使用约 48° 的固定斜俯视正交镜头。建设画面同时看见建筑地基、入口、道路边缘和鼠标落点。 |
| 近景 | V5 近景和最大缩放值设为 1.5，重点检查石梯踏面、岩棱、树根、火盆和脚点遮挡。 |

V5 美术对照使用固定机位。P3 拾取按射线的首个地表命中判定，验证滚轮锚点、北朝上的小地图和总览往返。可玩区外用延伸湖面、外围树林和近黑渐雾补景。实现顺序与边界验收见[V5 还原开发计划](moonlake-v5-reconstruction-plan.md#5-固定镜头15-倍近景与外围收边)。

## 7. 地图反馈、HUD 与特效

沿用顶栏、手牌、商店抽屉和岗位弹窗的现有布局及输入优先级。受光材质负责世界氛围，资源符号、选框、危险方向和文本使用独立的表现层。小地图底图按同一关卡坐标输出，重点显示地形、水域、资源、主城和视野框。缩远后以符号代替细节。建造模式的层次从地面到上依次是合法性格纹、建筑预览、入口箭头和失败文字。取最暗的夜景、最亮的岸线、林缘和商店展开四类背景测试标记。[玩法 HUD 与地图交互规格](../ux/gameplay-hud-map-and-workforce.md)

## 8. 资产规格与性能预算

下列规格是首批样区的候选上限。已有主城的 12 个网格、18 种材质与 512² 纹理先原样测量。表内预算适用于新增或需要优化的资产。

| 首批资产 | 生产起点 | 验证 |
| --- | --- | --- |
| 草、土、岩、湿岸和水材质 | 基础纹理优先 1024²，共享地形页上限 2048²。用世界坐标采样和区域权重混合。水面独立材质，色带与法线分开。 | 连续跨区无纹理跳变、矩形接缝和周期条带。 |
| 崖段、石梯、岸石 | 崖段单件 300–1,200 三角面，石梯单段 150–600，岸石单件 60–250。每件优先 1 个材质槽，复杂结构最多 2 个。 | 网格提供大轮廓和接地边，法线和颜色图提供细节。转角有对接锚点，踏面沿既有路径与标高。 |
| 针叶树与低矮植被 | 复用约 1,290 三角面、单表面的近景树。远景候选 200–400 三角面，保留冠幅和主枝簇。草簇、芦苇与小石单件 20–100 面。 | 按空间区块与材质批绘，以屏幕投影大小选择细节。初试树高小于 32 物理像素进入简化档，预留 15% 滞回，逐画幅校准。 |
| 主城与配套地面 | 先复核现有 GLB 比例、夜景和 4×4 逻辑占地。若材质切换成为瓶颈，优先合并重复木石材质和地台贴图，保留入口与屋脊剪影。 | 建设档能定位入口，临近建筑的占地清晰，切总览时资源和主城标记稳定。 |

模型交付 `.blend` 源文件与 `.glb` 运行文件，约定以 Godot 导入后的 Y 为上、原点贴底。纹理源保存 PNG，颜色图用 sRGB，法线和粗糙度用数据纹理，环境贴图启用 mipmap。每件登记稳定 ID、来源、尺寸、三角面、材质槽、脚点、占地或装饰标记、LOD 和实景证据。状态依次经过规格、候选、评审通过、接入和实机验证。

以 1080p 60 FPS、帧间 P95 ≤ 16.67 ms、P99 ≤ 25 ms 作为整关候选门槛。地图 3D 纹理常驻先以 256 MiB 为上限，统计 mip，并另外报告旧 2D 资源、实体、HUD、网格和渲染目标。用 Radeon 780M 与 RTX 3060 Ti 分别记录主线程、GPU、绘制调用、三角面和显存，4K 单列。场景覆盖密林近景、主城密集建设和实际战斗，另记录批量寻路尖峰。若超预算，先按区块裁剪林带批次、减密集阴影和远景碎饰，再测湖水材质。保留道路、主城和落点的辨识线索。[Godot MultiMesh 批绘与可见性](https://docs.godotengine.org/en/stable/classes/class_multimesh.html)

## 9. 生产顺序与验收

| 批次 | 交付 | 通过条件 |
| --- | --- | --- |
| A · 锁定风格样区 | 在现有 P3 选取 S6 下口、中转台、相邻湖湾与林缘，用同镜头做 P3 当前版、厚块版两组对照。另拍主城与平原，分别记录建设档、近景、常态夜间和黎明。 | 主城、崖体、石梯、湖岸、开阔地各有明确轮廓。近景可见体积，缩远后地面细纹退到角色和地形之后。由用户或项目美术负责人确认方向。 |
| B · 模块化生产 | 先定草土岩水材质和崖段、石梯、岸线接口，再补林缘变体、资源点底座及主城地面过渡。 | 先通过真实拖牌和农民往返。覆盖 S6 双向、1×1/2×2/4×4 落点、跨崖/临水拒绝与保牌，验证林缘占用隐藏和恢复。 |
| C · 整关复核 | 把已确认模块分区应用到平原、山区、湖岸、外围林，整理同镜头截图、资产清单和帧时间报告。 | 复核八梯、八资源、四出生点及小地图。覆盖 16:9、4:3、超宽与 4K 的交互截图，执行自然 60 分钟长局、暂停和重开，记录遮挡、帧时间与批量路径。正式入口切换另行评审。 |

禁用参考作品的角色模型、标志、建筑原型和 HUD 布局。场景禁用跨过硬崖的地基、可走区域中像障碍的装饰、暗示可建的窄湿岸、全域强对比碎纹和双重投影。美术负责人评审时集中确认厚块风格的夸张程度，以及夜间平原与主城之间的明暗差。确认后再将通过条款纳入正式美术圣经。
