# 月湖山谷 V5 还原开发计划

2026-11-10 · 首批实施中 · Story-039 P3 整关候选

目标是在 Godot 中按 V5 还原一张可操作的月湖山谷。宽幅对照里能看到左侧连续平原和上下两个林缘空位、右侧后伸的多层山体、前侧石梯和湖湾，以及山脚一座小主城。交付需同时通过同镜头视觉对照和关卡交互验收。

[V5 设计图](concepts/moonlake-3d-2026-11-09/moonlake-night-concept-v5.png) · [地图美术开发方案](moonlake-3d-art-development-proposal.md) · [P3 现状与证据](../../production/stories/story-039-moonlake-3d-level.md)

## 1. 先约定如何判断还原

在 P3 候选内保存一套**仅用于验收的固定斜俯视正交镜头**。对照输出使用 V5 的 1946×808 画幅、隐藏 HUD、固定夜间时点和风水动画相位。沿用约 48° 下俯、偏航 0°，以同一套镜头中心、尺度与裁切对齐全图。玩家操作镜头另支持 360° 旋转，画面宽幅仅用于美术对照。

在 V5 上分别描出山脊及草台边、湖岸水线、三段密林及两个开口、主城地基与门口、各可辨石梯的上下端及平台。记录参考图像素坐标、候选屏幕坐标和对应关卡格。图上的遮挡或连接不清楚时，以现有地图数据核对后标注，尤其不能凭图把任意一段石梯直接认作 S6。

| 对照对象 | 建议验收门槛，第一批灰盒时锁定 |
| --- | --- |
| 主城门口、可辨石梯入口、林缘空位中心、主要湖湾转折点 | 以 V5 像素坐标为基准，横纵偏差各控制在画幅对应边长的 1% 内，约 19×8 px。先量约定锚点，再看全图轮廓。 |
| 连片平原、山体、湖面、外围树林 | 逐区叠加半透明轮廓，建议各主要区域投影面积偏差不超过参考区面积的 10%。同时人工比对北部山脊、三段左林和两处空位，避免面积相近但位置或形状走样。 |
| 主城与树、崖的比例 | 量主城地台宽和屋脊高、邻树从根到冠尖的投影高度。地台在参考画幅约占 7% 宽，邻近成熟松树高过屋脊，旗杆单独量。前侧石阶和前后山脊在宽幅图上清楚分层。 |
| 夜景层次 | 同时看彩色和灰度对照。平原低对比，岩棱与踏面有明暗分层，湖边浪花断续，主城双火盆是局部暖点。水纹、树梢与草叶用短实景回放评审。 |

这些是制作目标。概念图中未显示的坡背、踏面深度和树后区域按关卡规则补齐。宽幅参考的尺寸误差与游戏的拾取、建造、导航正确性分别验收。

## 2. 按依赖顺序实施

| 步骤 | 开发内容 | 交付与通过条件 |
| --- | --- | --- |
| **01 · 整图取样和差异登记** | 保存 P3 当前宽幅、建设、近景截图。绘制 V5 的轮廓、锚点及空位蒙版，再叠上当前 196×80 关卡格。核对后山扩展区、两处林缘空位、湖岸和石梯映射。 | 交付同镜头基线、编号叠图、差异表。每项差异有区域、涉及格、视觉目标、是否影响通行和落点。 |
| **02 · 整图灰盒与旋转镜头** | 在独立 P3 候选中铺出平原、后山主台、前侧阶台、两处林缘缺口、主城脚点和全条湖岸。并行用灰盒验证 360° 旋转、1.5 近景、任意方向拾取及外围收边。 | 交付灰盒、V5 叠图和镜头原型。标出可走台地与边界景观。确认斜向射线能区分台顶、崖面和水面，湖岸及林缘转到背面也有连续的景观。通过后再进入正式建模。 |
| **03 · 做 S6、前崖与相邻湖湾样区** | 用现有高度场搭出 S6 两段踏面及转向平台，先沿用每级 5.6、平台 2.8 的 P3 表现基线。新做一组崖段直段、内外角、端头，配少量主要岸石。调整共享岩、土、水材质，校准崖唇和湿岸。 | 交付一段可玩样区。农民双向走完 S6，脚底与踏面连续。崖面拦住射线，水域、跨崖占地拒绝且保留卡牌与资源。保存宽幅、近景和沿路回放。 |
| **04 · 分区扩展整关地形** | 将样区资产应用到前侧阶台、宽阔后山、各段石梯和连续岸线。先拼接山脊、各层高台与湖岸大轮廓，再做坡脚、岩棱和石阶侧面。道路以实际连接为准贴地绘制。 | 交付整关 3D 地形候选。核对八处石梯、四处出生点、八个资源点和小地图一致性。模型转角无穿插、假路和可见拼缝，山顶与湖湾达到同镜头轮廓要求。 |
| **05 · 林带、主城与动效** | 复用主城和针叶树 GLB。布置左侧三段密林，留上下两块净草地，山后加连接林带。沿真实岸线延伸湖水，陆缘补外围树林及近黑渐雾。主城按图调整视觉比例，校验 4×4 占地。复用风动草簇、湖面材质和双火盆。 | 交付夜景美术候选。林缘两个空位清楚，树冠在石梯口留出视线，风动和水纹与暂停及重开同步。测 00:00、30:00、55:00、60:00 四个已用时点的表现。 |
| **06 · 整关验收与交付** | 跑开局、拖牌、资源采运、敌人进城、封路破障、镜头操作、暂停重开和一局自然 60 分钟对局。记录 1080p、4K 和不同画幅，检查密林近景、集中建造与战斗压力。 | 交付 V5 对照截图、差异清单、可玩候选、模型及材质登记、回归和性能报告。正式入口切换依据整关验收结果决定。 |

## 3. 地形与玩法的交接

当前权威关卡是 [level_001](../../src/levels/level_001.tres)，格长 36 个二维世界单位，对应 1 个三维水平单位。保留当前四林两石两铁的资源 ID、四个出生点、八条石梯和 S6 连接关系作为对照基线。原网格、高度场、射线和小地图各自输出调试层，逐个核对实际落点。

- **表现差异**由网格表面、低多边形结构和材质收敛。可以在禁走边界内修崖唇、向水域内修波浪、调整装饰林摆位。景观后山可以有草顶与背脊，用连贯崖面和林带说明边界。两处林缘空位画作净草地，是否可建取决于已核对的关卡格。
- **玩法差异**单列到 P3 候选关卡修订。若 V5 的后山扩展、湖岸形状或开口必须成为新可走、可建区域，同步改地形、层级、连接、拾取与小地图数据，并重新测资源运输距离、入口封堵、出生到城路线。修订结果通过后再应用到正式关卡。

## 5. 360° 镜头、1.5 倍近景与外围收边

### 操作镜头

- 固定约 48° 下俯，围绕当前镜头中心对应的地面焦点水平连续旋转一整圈。暂定按住 Q / E 向左或向右转。偏航从 359° 回到 0° 时姿态连续，平移始终按屏幕方向响应。暂定拖牌期间锁定旋转，以稳定放置落点。
- **1.5 按当前项目的绝对缩放值处理**，即 P3 的最大放大和近景档由 0.45 改为 1.5，初始建设档仍以 0.36 为基线。滚轮以有效地表上的光标点为锚，碰到镜头限位时优先守住边界。高倍率重点复核草叶、主城贴图、石阶踏面和岸线。当前 0.45 的近景验收只作历史基线。
- 小地图维持北朝上，用当前朝向投影视野四边形，裁到可玩范围内。M 总览暂定以北朝上显示，退出恢复进入总览前的焦点、倍率和偏航。Home 回到主城建设视角，暂定保留当前偏航。

### 拾取与交互

当前 P3 射线只遍历同一列，旋转后射线会跨行跨列。先改为遍历任意方向射线经过的网格，按从近到远校验格顶和高差边界，返回第一个命中面。共用现有高度场与关卡格，崖面、水面、景观带在前方时结束拾取，避免选中后方合法地块。选中建筑、拖牌预览、实际落点和缩放锚点共用变换和可见面判定。针对格边、角点和近似平行方向制定确定性的命中次序。[当前 P3 拾取实现](../../tools/moonlake_3d_level/presentation.gd)

### 边缘过渡

| 范围 | 实施要求 |
| --- | --- |
| 可玩边界 | 继续由关卡格决定通行、落点、资源与出生。外围补景属于独立表现层，始终拒绝建造和通行。 |
| 镜头边界 | 焦点可以移到可玩区边缘，同时根据当前倍率、偏航和实际可玩视口四角计算地面覆盖范围。斜向和宽屏下用实际投影限位，防止镜头一转就跳回或露出空区。 |
| 景观边界 | 东侧、东南侧等湖岸相邻区延伸低细节深色湖水。陆缘用树林、树后底色和地形背面补齐，再按世界位置平滑过渡到近黑夜雾。湖林交接用湿岸、岸石和疏林衔接。雾带位于外围，随相机移动能看到景深层次，HUD 和可玩区的道路、单位、建造提示保持可读。 |

使用简单的地表材质渐暗与外围雾带，在当前 GL Compatibility 上验证。外围林冠、崖背和湖面都要检查反向视角。按操作最远档、视口宽高和最不利偏航估算补景范围，再实机调整。参考[模块化地图的镜头与边界设计](../gdd/modular-level-map-system.md#9-镜头视口与缩远露图)。

## 6. 整关验收清单

- **视觉**。保存固定镜头的 V5、旧 P3、新 P3 三列对照，以及 S6、山顶、湖岸、两个林缘空位和主城近景。三列共用同一坐标基准和画幅。
- **交互**。用真实鼠标测试 1×1、2×2 建造与 4×4 主城占地，检查合法落点、占用、临水、跨高差和错误资源点。覆盖 S6 双向、矿点往返、建筑拆除后草簇恢复、小地图定位、M 总览、Home 回城及滚轮锚点。
- **镜头与收边**。在 0°、45°、90°、135°、180°、225°、270°、315° 检查平原、崖下、S6 和湖岸落点，并连续转完一圈。用 16:9、4:3、超宽画幅，在近景 1.5 和操作最远档分别移动到四边与四角，观察水林衔接、近黑渐雾、崖背露底和镜头突跳。边界外点击无有效落点，斜向镜头下临水拒建保卡，退出总览恢复原视角。
- **性能**。以 1080p 帧间 P95 ≤ 16.67 ms、P99 ≤ 25 ms 为原方案候选门槛，分别记录主线程、GPU、显存与批量寻路尖峰。4K 单独报告。整关压力场景超预算时，先调树木批次、远景细节和阴影。
- **交付**。保留 Blender 源文件、GLB、共享贴图、摆位与关卡差异记录。更新 Story-039 和开发进度，运行相关自动化、`tools/check_project.ps1` 与 `git diff --check`。

首批开工范围是 **步骤 01 和 02**。先拿到整图灰盒、地形差异表及可实际旋转和拖牌的镜头原型，再按步骤 03 做 S6 样区。

## 7. 首批实景差异
