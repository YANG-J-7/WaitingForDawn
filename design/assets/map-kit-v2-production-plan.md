# 模块化地图首批素材生产计划（提案）

> 2026-10-27；只完成规格，尚未生成、批准或接入。本表范围是地图环境与建筑融合，不扩展为整个游戏重制。
> 关联：[主方案](../gdd/modular-level-map-system.md)、[美术草案](../art/map-art-bible-v2-proposal.md)、[总表](asset-manifest.yaml)。

首批目标是用同一套零件搭两个不同布局的互动测试区，证明地形可换、规则可查、建筑贴地和镜头清晰；不同时制作第二、第三正式关卡。资产ID永久保留，取消后也不得复用。旧有MAP/BLD/UI命名ID保留，不批量改名。本批新规格使用ASSET编号。

| ID | 素材包 | 最低变体/结构 | 复用策略 | 优先级 |
|---|---|---|---|---|

上表“8件/12件起”为生产估算，不是能覆盖所有自由拼接的承诺。先用样区接口矩阵列出准确朝向和连接类型，再逐个核准；缺转角/端头不得以拉伸直段代替。环境结构不塞进方格小物件包。

分类边界：环境/地物/建筑落地为本批；主城、生产/防御建筑主体、农民、守卫、狼、卡面和HUD图标复用现有，属于外部依赖，不新增重复绘制ID；出生点与资源槽为数据，编辑器符号可程序绘制；风/水VFX先记录引擎材质规格，未批准天气不生产；音频、3D、角色/敌人/投射物动画排除本批。

每份[详细规格目录](specs/)记录用途、源有效尺寸、显示范围、镜头、格式/透明度、帧数、锚点、预算、依赖、目标路径、手写提示词与禁止项。目标路径为未来产物，不要求当前存在；总表不能用`file`字段谎报已生成图片。

生产顺序：材质对照 → 灰盒接口上的基础地表 → 稀疏场景参考（最多9类可见结构/物件）→ 独立结构件 → 建筑底座/林簇 → 两个布局的引擎预览。每次生成前重新查看基础图与场景参考，提示词明确二者是可见上下文；保存提示词和参考哈希。

先批准本清单的**范围**再批量生产，实际生成稿仍需用户或指定美术负责人逐项批准。当前`specified`表示有规格，`scope_approved=false`，不代表用户批准制作，也不代表技术/视觉验收。预算以共享纹理去重后统计，不把同一贴图实例重复计费；风格与技术检查都通过后才登记verified。
