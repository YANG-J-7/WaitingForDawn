# 系统 GDD：网格地图、清晰地形与单位寻路方案

> 状态：镜头边界、逻辑网格、寻路、精细地形格、建筑落地原型与高密度可复用草地已实现；水岸/崖壁正式地块与动态避让待实施
> 更新：2026-10-13
> 适用版本：Godot 4.7 Standard，Steam 单机原型

## 目标与游戏支柱

本方案解决三个已确认问题：镜头可以缩出地图边界、整张烘焙草地放大后模糊、建筑缺少落地感；同时把建筑、地形和单位移动统一到可测试的网格坐标。

服务的体验支柱：

1. 玩家能清楚判断哪里可建、可走、可采集。
2. 建筑像真正占据地块，而不是漂浮在背景图上。
3. 敌人、农民和守卫遵守同一地形规则，湖泊、树林和建筑可以可靠阻挡路线。
4. 视觉表现与玩法数据分层，后续替换美术不会破坏寻路和建造规则。

## 方案选择

| 方案 | 网格 | 优点 | 代价 | 结论 |
|---|---:|---|---|---|
| A | 36世界像素，80×45格 | 与2880×1620地图完全整除；接近现有32像素战斗单位；建筑能使用1×1、2×2、3×3占地 | 现有32像素射程和速度需要统一迁移 | **推荐** |
| B | 32世界像素，90×50格，地图高改为1600 | 复用现有`TILE_SIZE=32`最多 | 需要裁掉或重制20像素地图高度，破坏现有构图和精确16:9 | 不推荐 |
| C | 48世界像素，60×34格，地图高改为1632 | 单元少，路径计算更轻 | 建造粒度偏粗，狭窄湖岸和资源点误差大 | 不推荐 |

推荐采用A：**36像素逻辑格、80×45完整地图**。

## 玩家动词与核心循环

### 建造

1. 玩家拖起建筑卡。
2. 地图显示可建网格、建筑占地和入口方向。
3. 鼠标位置转换为目标格，建筑预览吸附到格中心或占地区域中心。
4. 系统检查地形、资源点、建筑、动态单位和出入口。
5. 合法时建造并写入占用格；非法时保留卡牌和资源并显示原因。

### 单位移动

1. 系统把当前位置和目标交互点转换为网格坐标。
2. `AStarGrid2D`计算格路径。
3. 单位沿格中心路径平滑移动，画面位置继续使用连续坐标。
4. 建筑、墙或地形改变后，只给受影响单位重新计算路径。

单位的权威路线由网格决定，渲染位置不强制逐格跳跃。

## 规则、状态和转换

### 地图层级

运行地图拆为以下层：

1. `GroundLayer`：无缝草地地块和草色变体。
2. `WaterLayer`：湖水和岸边连接块。
3. `CliffLayer`：坡顶、崖壁和坡脚连接块。
4. `GroundDetailLayer`：小石块、草簇、泥土斑等不影响规则的装饰。
5. `GridData`：80×45玩法数据，不直接显示。
6. `BuildGridOverlay`：只在拖动建筑、选择建造工具或调试时显示。
7. `ResourceProps`：树林、石矿、铁矿独立场景。
8. `Entities`：建筑和人物，按脚点Y排序。

现有2880×1620整图保留为构图参考和迁移底稿，完成地块重建后不再作为运行时草地底图。

### 单格数据

每格至少保存：

```text
terrain_type: grass | water | cliff | shore | road | ramp | resource
walkable: bool
buildable: bool
movement_cost: float
elevation: int
static_occupant_id: StringName
resource_site_id: StringName
```

MVP规则：

| 地形 | 可行走 | 可建造 | 移动代价 |
|---|---|---|---:|
| 草地 | 是 | 是 | 1.0 |
| 湖水 | 否 | 否 | 不可达 |
| 崖壁 | 否 | 否 | 不可达 |
| 坡顶草地 | 是 | 是 | 1.0 |
| 草地道路 | 是 | 是 | 1.0 |
| 岩壁坡道 | 是 | 否 | 1.0 |
| 岸边 | 是 | 否 | 1.2 |
| 空闲资源点 | 否 | 仅对应建筑 | 不可达 |

山坡高低差在MVP只用于标记崖壁阻挡，不增加伤害或射程数值。

2026-10-10按用户要求细化固定地图山区：草台可走可建，裸露岩石不可走不可建；跨岩面的坡道可走、不可建。岩面登记位于`design/levels/mountain-rock-cells.json`，由固定底图离线12×12取样/格并按18%岩面覆盖门槛细化，运行只读JSON。换图后必须重新登记并目检格边缘；不是运行时图片颜色碰撞，也不是通用高度图。

`mountain-resource-routes.json`定义72世界像素宽的主干、四矿入口和山台支路；显示与地形开放共用这份坐标。草地路可建，岩石坡道仍禁建，资源专用格及静态占用最后覆盖路网。水域不会被道路开放，道路不加速。当前2×2草台建造落点与主城连通已验证；建造后仍可能人为堵塞路网，封路处理与单位避让保持既有范围。

### 建筑占地建议

| 对象 | 占地格 | 说明 |
|---|---:|---|
| 箭塔 | 1×1 | 视觉可超出格，脚点必须在格内 |
| 城墙 | 1×1 | 建成后立即阻挡该格 |
| 民屋 | 2×2 | 入口设在靠主城一侧 |
| 农场 | 2×2 | 地表替换为耕地底座 |
| 伐木场 | 2×2 | 占用指定树林资源点 |
| 石矿场、铁矿场 | 2×2 | 占用指定矿点，入口格必须可达 |
| 兵营 | 2×2 | 守卫从入口相邻格生成 |
| 主城 | 4×4 | 以外围入口环作为农民交付与敌人攻击目标 |

静态建筑占用格为硬阻挡。移动单位不永久写入硬阻挡层，使用“当前格＋下一格预约＋局部避让”，避免多人互相堵死。

### 路径与阻挡

- 使用八方向移动，禁止穿越被两个正交障碍夹住的对角线。
- 农民前往建筑入口相邻格，采集后返回主城入口环。
- 敌人前往主城外围可攻击格；守卫在兵营半径内拦截。
- 普通建筑和城墙写入静态阻挡后触发局部路径失效检查。
- 若所有路线被封死，敌人选择造成封路的最近城墙或建筑，移动到相邻攻击格并破坏它；不得停在原地或穿过建筑。
- 动态单位只增加软代价，不直接修改全局A*固体格。

### 镜头

最小缩放根据实际地图视口动态计算：

```text
fit_zoom = min(viewport_width / map_width, viewport_height / map_height)
minimum_zoom = fit_zoom
default_zoom = fit_zoom
```

当前960×540逻辑视口与2880×1620地图均为16:9，因此`fit_zoom = 1/3`。缩小到此处后停止，不允许出现当前`0.25`导致的地图四周空白。

镜头中心限制考虑可见半宽和半高：放大后允许平移到地图边缘；处于全图倍率时中心固定在地图中心。非16:9窗口完整显示地图，并用统一深色边框填充剩余区域。

建议缩放档位为：全图倍率、0.5、0.75、1.0、1.25、1.5。滚轮仍以鼠标位置为锚点，但最终吸附到相邻档位，减少地块和像素抖动。

## 公式、单位与算例

### 坐标转换

```text
cell = floor((world_position - map_origin) / 36)
cell_center = map_origin + (cell + 0.5) × 36
```

例：世界坐标`(1380,1030)`转换为格`(38,28)`；对应格中心为`(1386,1026)`。主城迁移时应以4×4占地中心重新对齐，而不是保留任意像素坐标。

### 移动速度

速度统一以“格/秒”存储：

```text
world_speed = cells_per_second × 36
```

野狼当前1.4格/秒迁移后为50.4世界像素/秒。农民当前80像素/秒对应2.22格/秒，可取2.25格/秒作为初始值。

### 射程

箭塔和近战范围改为格单位，判定使用格中心的欧氏距离；视觉范围圈仍转换为世界像素绘制。

## 输入、反馈与无障碍

- 普通状态不常驻显示网格，避免破坏夜间地图观感。
- 拖动建筑时显示占地格：绿色合法、红色非法、黄色资源专用、蓝色入口和路径。
- 非法原因区分为湖水、崖壁、资源类型不符、建筑占用、单位占用和封死全部路线。
- 建筑落地增加三项视觉：地基/压平地面贴花、脚点接触阴影、落成时短暂尘土反馈。
- 资源建筑使用专用地表：伐木场显示树桩和木屑，矿场显示碎石坡道，农场直接替换2×2草地为耕地。
- 颜色之外同时使用格纹、图标和文字表达合法性，避免只依赖红绿颜色。

## 草地清晰度与建筑落地感方案

### 草地

1. 使用`assets/tilesets/moonlit_grass_detail_v3/`的4个627×627原生细草叶变体，每块显示为72×72世界像素、覆盖2×2逻辑格。36世界像素是玩法网格，不是贴图分辨率；草地采用与建筑接近的源纹理密度，避免最大1.6倍率下放大低分辨率像素块。末行不足两格时按比例裁源区域，不压缩完整地块。旧v1/v2保留作历史对照，最终视觉待用户目检。
2. 关闭VRAM有损压缩，使用Lossless导入；像素层使用Nearest过滤。
3. 不把生成草地缩放成整张背景。草地图集独立混铺，当前湖岸与崖壁使用`moonlit_terrain_detail.png`连续高细节底图及保坡遮罩，正式连接块仍待制作。底图3344×1882与2880×1620世界范围解耦，仅底图与保护源采用Linear，不降采样后2倍复制、不量化为64色；保护材质直接使用连续世界坐标UV。下方平原清理范围向内退让，保护重绘湖岸，不修改权威水域、网格或碰撞。资产尺寸与来源见`assets/map/README.md`。
4. 控制每格纹理对比度，避免缩远时形成噪点；大色块在地块层，小细节放到可按缩放隐藏的装饰层。

### 建筑

1. 所有建筑统一以“底部中心脚点”对齐占地区域。
2. 增加与占地一致的地基贴花，贴花绘制在建筑下方。
3. 增加4～8像素高的接触阴影，阴影不得脱离建筑脚点。
4. 建筑美术按占地规格重新校准：2×2建筑主体建议宽50～68世界像素，高45～72世界像素。
5. 建筑和单位进入同一Y排序层；高物体只遮挡位于其后方的单位。

## 跨系统接口与依赖

- `GridMapModel`：地形、静态占用、坐标转换和版本化存档的唯一权威数据。
- `GridPathfinder`：持有`AStarGrid2D`，只读取`GridMapModel`。
- `SettlementBuilder`、`WallManager`：提交占地查询和占用变更，不直接解析地图图片。
- `EnemyActor`、`FarmerAgent`、`BarracksGuard`：请求格路径并沿路径移动。
- `MapCamera`：读取地图边界和当前有效地图视口，计算全图倍率。
- `TileMapLayer`：只负责显示，不能成为玩法状态的唯一来源。

Godot官方文档将`AStarGrid2D`定位为部分二维网格的专用A*实现，并支持固体格和权重；`TileMapLayer`适合使用图集绘制大地图并承载碰撞、遮挡和导航信息。本项目仍建议把权威玩法数据放在`GridMapModel`，避免UI或美术节点持有核心状态。

## 边界条件与失败恢复

- 视口尺寸为0或场景尚未进入树时，镜头沿用上一次合法倍率。
- 建筑导致主城完全不可达时拒绝建造；若战斗中建筑销毁，释放占用并重新计算路径。
- 单位所在格因建筑落成变为阻挡时，先把单位推出到最近可走格，再写入建筑占用。
- 目标建筑销毁后，农民保留已采集货物并重新寻路回城，保持现有规则。
- 找不到完整路径时允许查询最近可达格用于反馈，但正式移动不得穿过固体格。
- 暂停冻结路径推进和预约时钟；重置清空动态预约、建筑占用和路径缓存。

## 验收标准

1. 960×540时镜头最低倍率恰为`1/3`，不能继续缩小；窗口尺寸变化后自动重算。
2. 任意镜头位置不显示地图边界之外的世界；非16:9窗口按设计显示统一边框。
3. 2880×1620地图对应80×45格，世界坐标与格坐标往返误差不超过0.01。
4. 所有建筑吸附网格，多格占用正确；湖水、崖壁和错误资源点拒绝建造且不消费卡牌或材料。
5. 100次随机合法建造中无建筑重叠、无单位被永久困在固体格内。
6. 敌人、农民和守卫不会穿过湖水、崖壁、树林资源点或存活建筑。
7. 墙体封路后敌人能选择阻挡物攻击；破坏后在0.3秒内恢复到主城的路径。
8. 草地在全图、1.0和最大1.6倍率截图中无明显大像素块，纹理密度接近主城；地块边缘无明显接缝。此次验证不代表既有崖壁与湖岸贴图也达到建筑纹理密度。
9. 每类建筑都有地基或地表替换、接触阴影和正确脚点，单位能按Y排序从建筑前后经过。
10. 完整回归保持通过，并新增镜头、网格转换、占用、封路、路径恢复和视觉截图证据。

## 风险与待验证假设

- 重新制作草地、岸线和崖壁地块是本方案最大的美术工作量；直接切割当前整图不能得到无缝且清晰的地块。
- 从直线移动迁移到网格路径会改变运输耗时和怪物到城时间，必须重新验证经济与波次平衡。
- 严格一单位一格会产生拥堵，本方案使用软预约；预约参数需要以20～50单位压力测试校准。
- 建筑可完全封路时，敌人攻击阻挡物的选择必须确定，否则会出现无解布局或卡死。
- 当前建议默认隐藏网格，只在建造和调试时显示；若用户希望常驻战棋网格，需要另行调整美术对比度和HUD信息密度。
