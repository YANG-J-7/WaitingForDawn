# 游戏概念：Waiting for Dawn（等待黎明）

> 状态：2026-09-14 已确定60分钟每局从零、击杀金币与商店抽牌、三卡升星、自由建造、大地图地形与天气；细则待设计
> 平台：Steam；暂以 Windows 键鼠作为验证基线，支持系统清单待定
> 引擎：Godot 4.7 Standard
> 开发形态：单机，核心对局按离线运行设计；平台服务待定

当前规则见[60分钟战役规则](sixty-minute-campaign-system.md)：一局60分钟，每局从零建设家园；主城存活至计时归零即胜利。击杀野怪获得金币，用于刷新商店和购买卡牌；3张同名同星手牌合成高一星卡，已建建筑不参与。在带地形与天气的大地图自由建设，普通建筑可放无单位空位，特定建筑要求特定位置。金币灰盒规则见[商店与升星系统](kill-gold-card-shop-fusion-system.md)，逐卡星级效果仍待细化。历史构思见[前轮讨论稿](long-session-strategy-direction.md)，平台决定见[Steam方向调整](../../docs/architecture/change-impact-2026-09-14-steam-single-player.md)。

## 一句话提案

一款面向Steam的2D像素家园经营与生存肉鸽游戏：玩家每局从零开始，在60分钟战役中建设家园、击杀野怪赚取金币，通过商店抽牌与三卡升星发展生产和防线，应对大地图中的地形、天气与生存威胁。

## 以下为旧版概念的讨论底稿

以下受众时长、节奏、MVP范围、十波胜利、硬克制与成功标准保留作历史比较，尚未按第二项方向逐节重写，不作为新版验收或已批准范围。当前程序仍为十波灰盒。

## 玩家幻想与目标受众

### 玩家幻想

玩家是末日边境聚落的守夜人兼管理者。每次兽潮间隙都要决定是让居民继续生产、购买防御卡，还是为尚未现身的怪物王收藏昂贵对策。玩家在同一个越来越危险的黑夜里，把脆弱营地发展成能够迎来黎明的最后堡垒。

### 目标受众

- 喜欢塔防、卡牌构筑和生存经营的 PC 单机玩家。
- 偏好单局目标明确、操作简单，但愿意反复优化决策的玩家。
- 单次游玩时间以约 5～15 分钟为宜，允许随时暂停和继续。

### 体验节奏

- **30 秒循环**：清空一波敌人 → 结算生产 → 查看六卡商店 → 免费选择或购买/刷新 → 建设并调整人口 → 开始下一波。
- **10 分钟循环**：守过10波兽潮 → 第6波后应对概率递增的怪物王与多王事件 → 使用提前收藏的配对卡解除击杀锁 → 击败至少一只王并迎来黎明。
- **长期目标**：解锁新的敌人、怪物王、配对卡和规则，并提高怪物王击杀数与通关成绩；黄金凤凰运气属于合法成绩因素。

### 失败与恢复

- 主城耐久降为0时失败并结束本局；第10波清空且主城仍存活时胜利。当前灰盒允许重新开局。
- 失败后保留已解锁的关卡信息、敌人图鉴和卡牌收藏记录；具体永久强化幅度需在系统设计阶段决定，避免排行榜过度依赖刷取。
- 玩家可以重新挑战整夜，利用已知的商店经济、普通敌人克制与怪物王卡池优化构筑；具体怪物王不提前预告。
- 广告续战停止排期；是否加入非广告续战及其代价待定。

## 核心循环

1. **白天布防**：开局只有一座主城；玩家在20秒内从固定3张资源建筑、3张防御建筑中免费选4张并完成初始布置。
2. **刷新押注**：玩家可不断支付递增金币刷新，寻找经济、防御、科技或随机怪物王克制卡。
3. **建设经营**：打出建筑、政策和科技卡，支付建造资源并调整人口岗位。
4. **波次防守**：怪物沿路线进攻；第6～10波普通怪潮每波增强10%，并可能出现一只或多只怪物王。
5. **硬对策验证**：怪物王只有在玩家拥有其配对卡时才能被击杀；卡牌不会根据王的出现定向匹配。
6. **结算成长**：第1波后每次随机展示6张卡并结算生产、食物、研究和维修；第10波清场且主城存活时通关，不要求必须击杀怪物王。

### 卡牌职责

- **建筑牌**：农场、伐木场、住宅、箭塔、城墙等，直接改变地图和产能。
- **政策牌**：征兵、加班、配给等，用一次性代价改变当日经营状态。
- **科技牌**：强化某一类建筑或解锁新机制，承担局内构筑方向。
- **战术牌**：路障、集火、修复等，为夜战提供有限主动操作。

卡牌不应成为脱离地图的独立数值游戏；每次选择都必须影响城镇、人口、资源或当晚防守。

## 游戏支柱

1. **波间的选择必须在下一波兑现**：不加入与防守结果无关的经营系统。
2. **少量规则产生真实取舍**：资源和卡牌类型保持精简，不以堆叠货币、品质和养成层制造复杂度。
3. **经营与布防共用同一套压力**：人口、空间和资源同时服务发展与生存，不能无代价兼得。
4. **短局可重玩、失败可理解**：玩家应能从兽潮预告和战斗反馈看懂失败原因，并在下一局改变策略。
5. **面向桌面单机体验**：键鼠交互清晰，规划本地存档、暂停恢复与可读的界面，不依赖持续联网。

## MVP 范围

### 必须包含

- 1 张紧凑地图，包含城镇核心、建筑格与 1～2 条敌人路线。
- 完整的20秒白天布防、单夜10波、六卡商店、免费选择、金币购买/刷新、放置、人口调配和波间结算循环。
- 木材、食物、石材、铁矿、金币、卡牌和王之对策全部只在当前局有效；人口作为独立岗位系统。
- 12～16 张卡牌，覆盖经济、人口、防御、科技和战术职责。
- 3种普通敌人、3种怪物王及3张永久生效的配对克制卡。
- 1个验证关卡、1个黑夜、10波兽潮；第6～10波出现王与多王事件。
- 本地存档、暂停、继续、失败重试、主城耐久与通关成绩记录。
- 规划本地通关次数与成绩记录；Steam 在线排行榜是否加入另定。
- 每局10%概率出现一次黄金凤凰；整局出现后不再生成，击杀获得1亿本局金币。
- 微信广告触发点与 SDK 接入从当前范围移除。

### 成功后再加入

- 更多地图、路线规则、敌人生态和关卡词缀。
- 新卡组、卡牌解锁、有限的局外成长和每日挑战。
- 好友榜、赛季榜或更细的同关积分排名。
- 更多科技分支、英雄单位、事件牌和环境变化。

## 明确不做

- 不做实时多人、联机合作或 PvP。
- 不做开放世界、自由建城或大型剧情战役。
- MVP 不做复杂装备、角色抽卡、卡牌品质、升星和多重付费货币。
- 不依赖服务端运行核心战斗；排行榜只接收可校验的最小成绩数据。
- 不制作语音、长动画、高分辨率逐帧演出或大量独立纹理。
- 不在每个昼夜或战斗过程中强制插入广告。

## 商业化边界

- 原微信广告商业化方案停用，历史记录见 [微信激励广告与单局商业化系统](wechat-ad-monetization-system.md)。
- Steam 版本的收费方式、价格、试玩版和追加内容策略待定，不能仅由平台选择推定为买断制。
- 不为原广告转化或广告收入指标调整当前难度；续战、成绩和成长需按新的单机体验目标设计。

## 视觉身份锚点

**“冷蓝月夜包围着一小块暖橙灯火：白天逐格生长的像素聚落，在夜色中化为抵挡黑色兽潮的最后堡垒。”**

视觉生产保留有限色板、统一像素网格和图集复用；桌面分辨率下的辨识度与性能预算待验证，不沿用微信包体限制。

## 原型假设与成功标准

### 首要原型

制作一个无正式美术的 Godot 2D 可玩原型：单地图、单夜10波、六卡商店、至少12张普通卡、3种普通敌人和3种怪物王，验证经济、防御、随机对策与硬击杀锁能否形成公平取舍。

### 待验证假设

1. 六张候选与前3波免费额度能够快速建立构筑，又不会让界面和决策负担过载。
2. 人口同时服务生产、研究和守军，能够自然连接经营与塔防。
3. 玩家能从失败复盘理解自己曾经错过或未购买的对策，而不是觉得系统从未提供通关可能。
4. 旧版单关 5～15 分钟是否适合新的单机目标，需在方向讨论和试玩中重新评估。

### 原型成功标准

- 新玩家无需口头解释即可完成一次“六卡选择/购买—建设—波次战斗—结算”。
- 测试者能指出至少两次有意义的取舍，并能解释失败的主要原因。
- 不存在一套明显无视来牌和敌人类型的固定必胜顺序。
- 完整10波流程控制在约15分钟内，且中断后可以继续。
- 原版首次挑战通关率8%～12%仅作为待复核的旧难度目标；保留普通局与彩蛋局分组观察，暂停广告辅助统计。
- 玩家能理解“主城被摧毁即失败、清空第10波且主城存活即胜利”；本地成绩的字段与展示验收后续细化。
- 桌面导出需记录包体、启动时间与性能，完成离线运行验证；目前未完成 Steam 发行验收。

## 主要风险

- **系统膨胀**：经济、人口、科技、卡牌和塔防容易各自扩张；必须用游戏支柱持续删减。
- **随机性挫败**：发牌可能掩盖策略；需通过候选牌分类、隐藏可解性与付费刷新排除数学必败，同时保留运气差异。
- **夜战参与感不足**：纯自动战斗可能沦为等待；用少量战术牌或集火指令验证合适的干预强度。
- **桌面布局压力**：地图、手牌和经营信息同时显示，需要验证不同窗口大小、UI 缩放与文字可读性。
- **桌面交付缺口**：存档、暂停恢复、设置、导出和离线运行需要独立实现与验证。
- **平台服务范围**：成就、云存档和在线排行榜尚未决定，不应提前形成 SDK 依赖。
- **开发资源有限**：创意由单人提出，范围必须以可验证原型为先，不承诺未经估算的发布日期。
