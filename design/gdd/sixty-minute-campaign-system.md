# 新版战役规则：60分钟家园建设与生存肉鸽

> 更新：2026-09-16
> 状态：胜利、初始资源、商店经济与合成通则已确定为灰盒基线；逐卡数值、地形与天气细则尚待设计
> 平台：Steam 单机；引擎沿用Godot 4.7 Standard
> 实现：当前代码仍是十波灰盒，本文件不代表功能已经实现

## 确定的设计基线

| 编号 | 用户已确定的规则 | 范围 |
|---|---|---|
| CAM-01 | 一局60分钟，每局新开、从零开始；守满60分钟且主城存活即胜利 | 取代45～90分钟范围和十波终局；不采用永久家园或家园传承 |
| CAM-02 | 增加抽牌系统；击杀野怪获得金币，金币用于刷新商店卡牌与购买卡牌 | 灰盒奖励、卡价、刷新费及阶段收入目标见经济与合成GDD |
| CAM-03 | 3张同名同星手牌手动合成高一星卡，已建建筑不参与 | 原型最高3星；不同星级改变属性与功能，各卡后续逐一设计 |
| CAM-04 | 建筑可放在地图没有单位的地方，少数特定建筑要求特定位置 | 普通建筑自由布置，特殊位置要求需逐卡声明 |

本文件是以上五项新版规则的当前依据。旧单夜十波、旧免费选卡阶段、固定格建造和历史家园传承提案不自动成为新版规则；未被用户改变的现有实现保留作复用参考。

## 1. 战役时长与从零开始

- 战役时长确定为60分钟；主城存活至计时归零即胜利，不添加60分钟之后的额外终战。主城在同帧被摧毁时判负。
- 每次新开战役重新建立家园，不继承上局建筑、人口、金币、材料、卡牌或星级，不设计跨局数值增强。
- “从零开始”指发展成果不跨局继承，不等于所有初始资源和人口数值都为0。灰盒开局为人口5/5，木材、食物、石材、铁矿各100，金币0；商店展示6张1星卡，玩家免费选择4张后进入计时战斗。
- 同一局存档继续与新开一局是不同操作。长局暂停、保存及继续仍需规划，不因每局重置而取消中途退出恢复。
- 计时建议使用有效游戏时间，暂停、退出期间不计时；速度倍率及计时口径待定。60分钟是设计规格，当前没有对应运行证据。

## 2. 野怪金币与商店抽牌

主循环：建设和安排战力 → 击杀野怪 → 获得本局金币 → 购买当前需要的牌或花金币刷新 → 布置建筑或保留卡牌凑升星 → 提高经营与战斗能力。

本次将用户所说“抽排”按“抽牌”理解为随机商店出牌和刷新，不擅自增加独立付费卡包、保底或第三种货币。

新版灰盒以击杀野怪为标准金币来源，旧金矿被动产金在首个原型中停用；其他事件奖励尚未批准。六格商店、18张手牌上限、2～6刷新费用及6/9/12卡价带以[击杀金币、商店抽牌与三卡升星系统](kill-gold-card-shop-fusion-system.md)为准，旧版开局20金币、12张库存和10/15/20递增刷新价不再作为新版参数。

实现时需要验证的边界：

- 哪些敌人属于可领奖野怪，是否有中立营地、刷怪和重生；攻城敌人与野怪是否共用奖励规则。
- 击杀奖励自动入账还是掉落拾取；建筑、守卫和其他单位击杀的归属；每只怪仅结算一次，退出清理与重置不应发奖。
- 卡池权重和逐卡价格仍待逐卡设计；购买、刷新、售罄、容量不足和扣款失败必须保持金币与卡牌事务一致。
- 金币增长与抽牌升级之间的平衡：保留金币可以买确定的牌，刷新是在为目标牌支付机会成本；避免强者靠更多击杀无限拉开差距，也避免没有第一批战力就没有金币的开局死循环。
- 卡牌购买与建筑材料成本是两个独立问题。用户已确定金币买牌，打出后是否继续消耗木材等材料尚未改变或重新确认；后续设计需明确，不能悄悄合并或取消。

## 3. 三卡升星

已确定：消耗3张一样的卡牌，产出一张提升一星的卡；星级变化可以包含属性与功能变化，不能统一假定为固定百分比加成。

“一样”确定为同名、同星，且只合成手牌：3张1星箭塔卡→1张2星箭塔卡；3张2星→1张3星，共需9张基础1星卡。原型最高3星，正式上限在逐卡设计和试玩后复核；各卡具体星级效果后续一一设计。

通用规则已经确定：玩家手动确认；不允许混合星级或自动连锁；合成不收金币或材料；满手牌可以合成，但购买不会临时超容或自动触发合成。出售、拆除返还及星级与稀有度的关系不属于首个原型，后续逐卡与商店扩展时再决定。

拟定一致性要求：3张来源实例只能被消耗一次，合成失败不吞卡；新卡应保留正确卡种、星级与独立实例标识。每张卡后续填写各星属性、功能变化、价格、占地及建造条件。

核心取舍：立即打出三张低星牌扩张覆盖，或保留手牌凑出更强的单张牌。短原型需要实际观察两种选择是否都有成立场景。

## 4. 自由建造与特殊位置

- 普通建筑不要求固定建造格或建筑类别专用区域，可在地图内无单位占用的位置放置；既有建筑、主城和生物占地需检查整个建筑占地范围，不能只检查中心点。
- 特定建筑可要求特定位置；树林伐木场、矿脉采矿建筑可以作为沿用候选，但最终名单与对应地形需逐卡明确。
- 地形的通行与可建造属性应分别设计。水面、陡坡、道路等是否可建普通建筑尚未确定，不以添加地形为由默认扩大禁建区。
- 拖牌时建议显示可放置区域与具体失败原因；失败不扣卡、不扣材料、不占地。镜头缩放和平移后仍需正确校验世界坐标。
- 建造后阻断通路、单位暂时经过落点、高星建筑变大和天气期间地块变化都需要边界规则。

## 5. 大地图、地形与天气

新增地形与天气系统已确定，以下内容是候选，未批准数量、效果或参数。

| 系统 | 候选内容 | 希望产生的决策 |
|---|---|---|
| 地形 | 平地、森林、山地、水域与资源带 | 家园建在哪里、往哪侧扩张、运输线和防线如何布置 |
| 天气 | 雨、雾、寒冷或干旱 | 是否储粮、提前运输、调整防守或延缓扩张 |
| 地图结构 | 不同资源分布、通路与野怪位置 | 靠近资源可降低运输成本，也可能更接近危险 |

地图“大”应由可探索/经营的区域、运输耗时和战略距离定义，不直接把1400×600乘一个倍数当成完成。固定地图、随机地图或手工区块组合、迷雾与探索方式、野怪激活范围均待选定。

天气不能只作为画面装饰，但其影响需可预告和解释，并提供应对手段。天气持续时间、影响对象、效果叠加/结束恢复、暂停与读档、性能和可读性均需后续规格。地形若阻挡移动或改变路径，必须同步设计寻路；当前直线移动不能直接证明能适配河流或山体。

## 6. 系统之间如何形成经营取舍（建议稿）

下列关系用于指导后续原型；经济与合成规则以对应GDD为准，具体天气效果仍待设计。

| 系统衔接 | 玩家选择 | 后续设计必须回答 |
|---|---|---|
| 开局与击杀经济 | 第一笔投入用于生产还是战斗 | 开局资源能否建立最低战力，首批野怪是否可处理，避免金币和战力互相卡住 |
| 金币与商店 | 买眼前有用的牌，还是刷新寻找同卡 | 刷新频率、同卡出现率与击杀收入能否支持60分钟内形成构筑 |
| 合成与建造 | 用低星建筑扩张覆盖，还是保留卡牌等待升星 | 合成范围、占地与功能变化是否让两种选择都有适用场景 |
| 大地图与经济 | 靠近家园稳定生产，还是向外围扩张 | 远端资源或野怪收益能否覆盖运输、人口与防守成本 |
| 地形与防线 | 利用地形集中防守，还是保护分散的资源点 | 单位可达性、自由放置和封路后的行为是否一致 |
| 天气与运营 | 提前储备、调整岗位或改变扩张计划 | 预报提供多长反应时间，影响哪些系统，天气结束后如何恢复 |

建议首轮天气只选择一种清晰的经营影响，例如雾影响视野，或降雨影响某类地面运输；这是二选一的原型素材，不同时假定全图减速、减产和降射程。可影响对象、幅度、持续时间与应对措施在天气GDD中明确。

建议首轮大地图先验证几个相互连通、具有不同经营价值的区域，再决定最终尺寸与生成方式。每个扩张点都应有可说明的收益、占领/防守成本与返回路径；不通过拉长空路程凑足60分钟。

建议按以下发展重点组织60分钟内的节奏，时间划分不改变用户固定时长，也不额外增加60分钟后的流程：早期保证供给和基础战力，中期形成抽牌与升星取舍并向外扩张，后期考验地形利用、天气应对和资源分配。具体阶段时间点与敌人编成仍待设计；终局为60:00主城存活即胜利。

## 后续设计与验证

60分钟结束规则与合成参与范围已经确定。商店/击杀经济与卡牌合成详见[击杀金币、商店抽牌与三卡升星系统](kill-gold-card-shop-fusion-system.md)；下一步先实现10～15分钟短原型，再设计地图地形与单一天气原型。逐卡星级功能由用户后续一一设计，不提前填充。

Story-024已接通“开局可战斗→击杀入账→买牌/刷新→三合一→合法建造”的短循环，并通过自动化验证；两局10～15分钟自然试玩尚待完成。试玩通过后再加入地形和一种天气验证取舍，最后扩展至完整60分钟。

需验证的新边界包括：新局清空所有发展状态；计时与胜负优先级；击杀重复回调不重复发奖；购买/合成失败原子性；星级功能正确；地形下路径可达；天气切换与存档恢复一致；60分钟自然战斗中的收益与卡牌升级节奏。当前仅进行方向文档校验，没有运行这些玩法验证。
