# 系统 GDD：卡槽拖放建造

> 版本：0.2  
> 状态：Godot灰盒通过，微信真机触控待复核  
> 权威范围：卡牌选择后的拖动、落点校验、失败恢复与触控反馈

## 目标与游戏支柱

让“选卡—进入手牌—打出—建造”成为清晰的空间动作。六张商店牌只负责选择，已选择卡进入游戏界面的独立手牌卡槽栏，再从手牌栏拖到地图合法格位。

## 玩家动词与核心循环

查看六卡选择区 → 完成规定数量的选择 → 手牌栏整体出现并装入全部已选卡 → 从手牌栏按住拖动 → 松手建造 → 成功后从手牌栏移除。

## 规则、状态和转换

- 商店展示：六张牌可点击选择，但展示牌本身不可拖动。
- 选择未完成：手牌栏隐藏，不逐张展示已选牌。
- 选择完成：第1波选满4张时，独立手牌栏整体出现并一次性装入4张；资源卡只投放聚落格，箭塔只投放防御格。
- 拖动中：使用卡面副本作为拖动预览，不移动原卡槽。
- 合法落下：调用既有建造命令；仅建造成功后扣资源并锁卡。
- 非法落下：不扣资源、不锁卡、不改变格位，卡保留在原槽。
- 已使用：成功建造后从手牌栏移除，商店展示位显示已使用。
- 战斗或暂停：战斗阶段禁止拖动；暂停不改变卡牌状态。

点击卡后再点击地图格的旧路径作为键鼠和无障碍备用输入保留，与拖放共用同一建造命令。

## 公式、单位与算例

拖放不引入新数值公式。触控开始位移使用Godot默认拖动阈值；拖动预览至少保持卡槽文字可辨认。

算例：玩家在六卡选择区选择伐木场，伐木场进入手牌栏。玩家从手牌栏拖到空聚落格；若木材不少于35，则原子扣除35木材、生成伐木场并移除该手牌；拖到防御格或已占格时，余额与手牌均不变。

## 数据与可调参数

| 参数 | 默认值 | 说明 |
|---|---:|---|
| 第1波手牌栏上限 | 4 | 对应开局免费选四 |
| 聚落格数 | 3 | 当前灰盒值 |
| 防御格数 | 1 | 当前灰盒值 |
| 点击备用输入 | 开启 | 后续可在真机测试后调整 |

## 输入、反馈与无障碍

- 选满前只显示六卡选择区；选满后才显示独立手牌栏。商店牌显示“已加入手牌”，手牌槽显示“拖到地图”，已使用牌从手牌栏移除。
- 拖动时显示卡面副本；合法目标由按钮悬停/触控反馈表示。
- 失败原因继续写入布防提示区，如“资源不足”“格位已占用”。
- 不只依赖颜色，状态必须有文字；点击放置继续可用。

## 跨系统接口与依赖

- 手牌栏UI只产生 `card_drop_requested(card_index, target_type, target_index)` 意图，不拥有选择、卡牌库存或经济状态。
- `OpeningDraft`拥有选择与锁卡状态。
- `SettlementBuilder`与主场景防御建造流程拥有合法性校验和原子扣费。
- 建造成功后继续通知岗位系统刷新岗位列表。

## 边界条件与失败恢复

- 不在手牌栏、已锁卡、战斗中、类别不匹配、无效索引、资源不足或格位占用均拒绝。
- 拖到卡槽、道路、主城或界面空白处时自动取消，不产生状态变化。
- 同一张卡连续释放或重复事件只能成功一次。
- 鼠标拖动与触屏拖动共享命令路径；微信真机触控阈值留待平台验证。

## MVP 与延后内容

MVP包含独立的四格开局手牌栏、三聚落格、一个箭塔格、拖动预览和文字反馈。延后内容包括格位高亮动画、拖动轨迹、取消区、十二格跨波储备栏、多防御建筑预览和震动反馈。

## 验收标准

1. 六张商店展示牌本身不可拖动；第1波选1～3张时手牌栏隐藏，选满4张后手牌栏整体出现并生成4个对应卡槽。
2. 资源卡可投放空聚落格，但不能投放箭塔格；箭塔卡规则相反。
3. 合法投放复用现有扣费与建造逻辑，并锁定已使用卡。
4. 无效落点、资源不足、格位占用和重复投放不扣费、不锁错卡。
5. 成功建造后手牌从栏中移除并立即更新岗位列表；失败时手牌保留。
6. 点击备用路径和Story-001～006回归继续通过。

## 风险与待验证假设

- Godot桌面拖放在微信触屏导出上的手势阈值与取消行为需要真机复核。
- 960×540手牌栏空间有限，拖动时手指可能遮挡落点；后续可能需要放大预览或目标吸附。
- 商店区与手牌栏必须有清楚的层级差异，避免玩家误以为商店展示牌仍能直接打出。
