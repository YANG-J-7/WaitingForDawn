# 系统 GDD：卡槽拖放建造

> 版本：0.7
> 状态：第1～4波跨波手牌、自由城墙和兵营格Godot灰盒通过，微信真机触控待复核
> 权威范围：卡牌选择后的拖动、落点校验、失败恢复与触控反馈

## 目标与游戏支柱

让“选卡—开始战斗—显示手牌—打出—部署”成为清晰的阶段动作。六张商店牌只负责选择；进入战斗后，已选择卡才进入战斗界面底部的独立手牌栏，并可拖到地图合法位置生成建筑或单位。

## 玩家动词与核心循环

查看六卡选择区 → 完成规定数量的选择 → 点击迎战 → 进入怪潮战斗并显示底部手牌栏 → 从手牌栏拖到地图 → 生成建筑/单位 → 成功后从手牌栏移除。

## 规则、状态和转换

- 商店展示：六张牌可点击选择，但展示牌本身不可拖动。
- 选卡阶段：无论选择了几张，手牌栏与地图投放格都隐藏；选满4张只会启用“迎战”。
- 战斗开始：点击迎战或倒计时结束后，六卡选择面板收起，底部手牌栏整体出现并装入当前对局库存，地图投放格开放；第1波初始为4张已选卡。
- 波间保留：清场进入商店时隐藏手牌栏，但未使用卡仍保留在对局库存；第2波免费选择2张后与旧牌合并，重新进入战斗时一起显示。
- 战斗部署：怪潮正常移动与攻击时仍可拖牌；资源卡只投放聚落格，箭塔只投放防御格，兵营只投放兵营格；城墙可投放地图可建造区域内任意无单位位置。
- 拖动中：使用卡面副本作为拖动预览，不移动原卡槽。
- 合法落下：调用既有建造命令；仅建造成功后扣资源并锁卡。
- 非法落下：不扣资源、不锁卡、不改变格位，卡保留在原槽。
- 已使用：成功建造后从手牌栏移除，商店展示位显示已使用。
- 暂停：暂停时禁止新拖动并冻结怪潮；恢复后继续使用剩余手牌。当前灰盒先验证战斗拖放，完整暂停输入锁定后续补齐。

点击卡后再点击地图格的旧路径作为键鼠和无障碍备用输入保留，与拖放共用同一建造命令。

## 公式、单位与算例

拖放不引入新数值公式。触控开始位移使用Godot默认拖动阈值；拖动预览至少保持卡槽文字可辨认。

算例：玩家选中伐木场等4张牌并点击迎战。怪潮开始后底部出现4张手牌；把伐木场拖到空聚落格，若木材不少于35，则原子扣除35木材、生成伐木场并移除该手牌。拖错位置时余额与手牌均不变。

## 数据与可调参数

| 参数 | 默认值 | 说明 |
|---|---:|---|
| 第1波手牌栏上限 | 4 | 对应开局免费选四 |
| 普通卡库存上限 | 12 | 跨波保留；取得新牌前检查容量 |
| 聚落格数 | 3 | 当前灰盒值 |
| 防御格数 | 1 | 当前灰盒值 |
| 城墙地图投放面 | 1 | 覆盖可建造地图；支持多面独立城墙 |
| 兵营格数 | 1 | 兵营专用；生成岗位对应的守卫 |
| 点击备用输入 | 开启 | 后续可在真机测试后调整 |

## 输入、反馈与无障碍

- 选卡阶段只显示六卡选择区，卡面显示“已选择”；点击迎战后，底部深色铜边“部署手牌”栏出现，使用较高的卡片比例承载名称、类别、建造成本与“拖到地图部署”。
- 拖动时显示卡面副本；合法目标由按钮悬停/触控反馈表示。
- 失败原因继续写入布防提示区，如“资源不足”“格位已占用”。
- 不只依赖颜色，状态必须有文字；点击放置继续可用。

## 跨系统接口与依赖

- 手牌栏UI只产生 `card_drop_requested(card_instance_id, target_type, target_index)` 意图，不拥有选择、卡牌库存或经济状态。
- `OpeningDraft`拥有第1波选择状态，`InterwaveDraft`拥有波间商店选择状态。
- `RunCardInventory`以唯一实例ID保存最多12张跨波普通卡；同种卡的多个实例不会互相覆盖。
- `SettlementBuilder`、`WallManager`、`Barracks`与主场景防御建造流程拥有合法性校验和原子扣费。
- 建造成功后继续通知岗位系统刷新岗位列表。

## 边界条件与失败恢复

- 不在手牌栏、已锁卡、非战斗/非合法建设阶段、类别不匹配、无效索引、资源不足或格位占用均拒绝。
- 拖到卡槽、道路、主城或界面空白处时自动取消，不产生状态变化。
- 同一张卡连续释放或重复事件只能成功一次。
- 鼠标拖动与触屏拖动共享命令路径；微信真机触控阈值留待平台验证。

## MVP 与延后内容

MVP包含战斗界面底部动态手牌栏、十二张跨波普通卡库存、三聚落格、一个箭塔格、城墙自由投放面、一个兵营格、战斗中拖动预览和文字反馈。延后内容包括其他建筑自由落点、网格吸附、合法性高亮、拖动轨迹、取消区和震动反馈。

## 验收标准

1. 六张商店展示牌本身不可拖动；整个选卡阶段手牌栏隐藏，选满4张并进入战斗后才在底部生成4个手牌槽。
2. 战斗进行时资源卡、箭塔卡与兵营卡只能分别投放空聚落格、箭塔格和兵营格；城墙卡只接受地图空位，不能覆盖单位或建筑。
3. 合法投放复用现有扣费与建造逻辑，并锁定已使用卡。
4. 无效落点、资源不足、格位占用和重复投放不扣费、不锁错卡。
5. 成功建造后手牌从栏中移除并立即更新岗位列表；失败时手牌保留。
6. 点击备用路径和Story-001～006回归继续通过。
7. 第1波未使用手牌跨波保留，第2波免费取得2张后合并显示；重置时全部清空。

## 风险与待验证假设

- Godot桌面拖放在微信触屏导出上的手势阈值与取消行为需要真机复核。
- 960×540手牌栏空间有限，拖动时手指可能遮挡落点；后续可能需要放大预览或目标吸附。
- 底部手牌栏会占用约22%的逻辑画面高度；需要在后续美术版中避免遮挡敌人、主城与重要落点。
