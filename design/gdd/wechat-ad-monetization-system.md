## 目标与游戏支柱

本系统以玩家主动选择的激励广告为主要收入来源。目标不是把每局可见广告数量推到最高，而是在不打断战斗、不制造数学必败、不把广告变成通关门票的前提下，提高完整观看率、每局广告收入和长期留存。

设计原则：

1. 广告只出现在失败结算、波间商店和最终结算等自然停顿点。
2. 按钮必须提前说明奖励、限制和对当前局的影响；不使用误触、假关闭或强制倒计时。
3. 广告奖励提供第二种机会，不直接发放胜利、怪物王克制卡或无限金币。
4. 影响当前局战力的广告必须记录 `ad_assisted=true`，与纯净竞技最佳成绩分离。
5. 每局广告总预算是体验上限，不因广告加载失败、切后台或重复回调被错误消耗。

专业评审取舍：游戏设计与制作人视角优先保证广告价值和收入，UX视角限制打断与诱导，玩法程序与QA视角保证恢复、发奖和排行幂等。

## 玩家动词与核心循环

玩家动词：查看广告奖励、主动观看、关闭、重新挑战当前波、正常结束本局。

MVP广告循环：

1. 主城被摧毁，战斗冻结并生成失败复盘。
2. 系统判断本局是否还有广告预算、广告是否可用，以及重整普通怪是否可能改变结果。
3. 合格时显示一次“命运重整”；玩家可选择观看或直接结束。
4. 完整观看后恢复到本波起点，只重新生成同等威胁预算的普通怪。
5. 怪物王计划、怪物王种类和数量、黄金凤凰计划保持不变；玩家重新挑战本波。
6. 若再次失败则正常结束；若最终胜利则计入累计通过次数，并标记为广告辅助通关。

## 规则、状态和转换

### 广告状态机

```text
不可用
  └─ 广告加载成功且满足触发条件 → 可展示

可展示
  ├─ 玩家拒绝 → 返回失败结算
  └─ 玩家点击 → 展示中

展示中
  ├─ 加载/播放错误 → 返回失败结算，不消耗次数
  ├─ 提前关闭 → 返回失败结算，不发奖励
  └─ 完整观看 → 奖励事务处理中

奖励事务处理中
  ├─ 已处理事务 → 返回既有结果
  └─ 首次处理 → 消耗广告预算 → 恢复本波 → 10秒整备 → 战斗
```

广告展示期间游戏逻辑必须冻结。UI只提交观看意图，不能自行恢复波次或发放奖励。

### 单局广告预算

- MVP硬上限：每局最多完整观看并领取1次激励广告，仅用于失败续战。
- 延后实验硬上限：每局最多2次已领奖激励广告，不因触发点增加而突破。
- 两次广告开始展示的间隔不得短于120秒。
- 同一广告位每局最多成功领取1次奖励。
- 加载失败、展示失败和提前关闭不扣除预算，但同一失败界面最多自动重试加载1次。
- MVP不使用强制插屏、常驻横幅或战斗中广告。

### “命运重整”失败续战

失败界面文案：

> 观看激励视频，重新挑战第X波  
> 普通怪物重新组合；怪物王与黄金凤凰不变  
> 本局仅可使用1次

完整观看后的处理：

- 恢复本波开始前的权威快照：主城和建筑耐久、资源、卡牌储备、王之对策、人口岗位、科技、战术牌、冷却与本局标记。
- 不重新打开本波商店，不允许看见怪物王后购买新卡。
- 给予10秒整备，只允许重新摆放允许移动的单位、分配人口和调整集火优先级；不能免费建造或撤销波前已经支付的交易。
- 使用新的普通怪编成种子重新生成普通怪，但最终普通怪威胁预算必须与原编成一致。
- 普通怪类型与比例可以改变，路线数量和地图规则不改变。
- 怪物王是否出现、实例数量、具体种类、硬克制需求全部读取原本的冻结计划，不重新进行概率判定。
- 黄金凤凰的本局判定、出现波次、已出现/已击杀/已发奖状态全部冻结，不能通过续战生成或重复领取。
- 设置 `revived=true`、`ad_assisted=true` 和 `ad_continue_used=1`。

若失败时仍存在生命锁为1且玩家没有对应克制卡的怪物王，重整普通怪无法改变数学结果，因此不展示广告按钮，改为明确提示“缺少××对策，重整普通怪无法继续”。

### 普通怪重整算法

```text
原威胁预算 = sum(原普通怪威胁点)
重整目标预算 = 原威胁预算
重整种子 = hash(run_seed, wave_index, "ad_normal_reroll", ad_continue_used + 1)
允许预算误差 = 0；无法精确组合时使用低威胁怪补足差额
```

重整改变编成关系而不是直接降低难度。其价值来自让玩家现有建筑克制到不同类型的普通怪，以及获得一次重新布防和纠正操作的机会。

### 排行榜公平

- 所有唯一胜利，包括广告续战胜利，都使玩家的累计 `clear_count` 增加1。
- 主竞技榜的“最佳成绩”只接受 `ad_assisted=false` 的纯净胜利。
- 广告辅助胜利保存在个人记录，显示“续战通关”，不覆盖纯净最佳成绩。
- 后续若加入只影响局外图鉴进度的结算广告，不把已经完成的胜利标记为广告辅助。
- 排行提交必须包含 `ad_assisted`、`ad_continue_used` 和唯一 `run_id`。

### 延后广告实验

以下广告位默认关闭，只有MVP数据满足体验护栏后才逐项A/B测试：

1. **商队改运**：第4波后商店提供每局一次自愿广告，完整观看后免费刷新当前6张未取得卡；不恢复免费选卡额度、不赠送金币、不重置付费刷新价格。使用后标记 `ad_assisted=true`。
2. **战后图鉴整理**：胜利或最终失败后，可用本局剩余广告预算观看一次，使本次局外图鉴研究进度翻倍；不影响当前局成绩、资源或排行榜。

实验启用优先级为“失败续战 → 战后图鉴 → 商队改运”。商店广告直接影响胜率和排行公平，最后验证。

## 公式、单位与算例

### 每开始一局的广告收入

```text
每局完整广告数 = Σ(广告位获得展示资格 × 点击 × 成功播放 × 完整观看)
每局广告收入 = 每局完整广告数 × 激励广告eCPM / 1000
```

eCPM由平台、用户和时段决定，游戏不写死收入金额；优化重点是有价值触发点的点击率、完整观看率和次日留存，而不是单纯增加广告位。

### 广告续战后的总体通关率

```text
总体通关率
= 纯净通关率
+ (1 - 纯净通关率)
  × 续战广告点击率
  × 广告完整观看率
  × 续战后最终通关率
```

算例仅用于说明：纯净通关率8%，广告点击率40%，完整观看率90%，续战后20%玩家最终通关：

```text
8% + 92% × 40% × 90% × 20% = 14.624%
```

因此“约10%”必须明确指纯净首次挑战通关率；广告辅助总体通关率单独报告，不能靠增加必败局抵消广告救回的胜利。

## 数据与可调参数

| 参数 | MVP默认值 | 建议范围 |
|---|---:|---:|
| 失败续战次数 | 1次/局 | 固定1 |
| MVP已领奖广告上限 | 1次/局 | 固定1 |
| 延后实验总上限 | 2次/局 | 1～2 |
| 广告最短间隔 | 120秒 | 90～180秒 |
| 续战整备时间 | 10秒 | 8～15秒 |
| 普通怪预算变化 | 0% | 固定0% |
| 广告自动加载重试 | 1次/失败界面 | 0～1 |
| 强制插屏 | 关闭 | MVP固定关闭 |

必要事件漏斗：`ad_eligible`、`ad_offer_shown`、`ad_clicked`、`ad_show_started`、`ad_show_failed`、`ad_closed_early`、`ad_completed`、`ad_reward_granted`、`ad_continue_wave_started`、`ad_continue_run_won`。

每个事件至少包含：`run_id`、广告位、波次、失败原因、是否存在王、王数量、是否有全部对策、凤凰状态、会话时长和客户端版本。不得上传不必要的个人信息。

收入指标：每开始一局完整广告数、每活跃玩家日完整广告数、广告完整观看率、每局广告收入。体验护栏：广告后立即退出率、平均单局时长、次日留存、纯净通关率、辅助通关率和广告按钮误触率。

## 输入、反馈与无障碍

- 广告按钮始终使用“观看广告 + 明确奖励”的完整文案，不只显示播放图标。
- 同屏保留“结束本局/重新开始”普通按钮，且不得弱化、遮挡或延迟出现。
- 广告不可用时隐藏观看按钮并显示正常重试路径，不让玩家反复点击空广告位。
- 播放失败或提前关闭后提示“未完整观看，未消耗本局续战机会”。
- 完整观看后先显示“普通怪已重整，怪物王保持不变”，再进入10秒整备。
- 不只靠颜色区分纯净与续战成绩；同时显示文字标签和图标。
- 关闭震动、降低闪烁和字幕设置同样作用于广告前后的游戏反馈。

## 跨系统接口与依赖

### 输入命令

- `request_rewarded_ad(placement_id)`
- `decline_ad_continue()`
- `confirm_continue_setup()`

### 输出事件

- `rewarded_ad_availability_changed(placement_id, available)`
- `rewarded_ad_completed(placement_id, reward_transaction_id)`
- `rewarded_ad_failed(placement_id, error_class)`
- `wave_checkpoint_restored(run_id, wave_index)`
- `normal_wave_rerolled(wave_index, old_composition_hash, new_composition_hash, threat_budget)`
- `run_ad_assistance_changed(ad_assisted, ad_continue_used)`

### 依赖边界

- 平台适配层只负责广告加载、展示和完成回调，不持有战斗、经济或排行状态。
- 广告奖励服务以 `run_id + placement_id + attempt_index` 作为幂等事务键。
- 波次系统拥有权威快照、普通怪生成和冻结的怪物王/凤凰计划。
- 排行榜只读取对局摘要，不自行推断玩家是否使用广告。
- 本地存档保存广告预算、奖励事务、续战标记和波起点快照；重启应用不能恢复已消耗的广告次数。

## 边界条件与失败恢复

- 广告完整观看但回调重复：只发放一次奖励。
- 广告完整观看后应用崩溃：下次启动根据已提交奖励事务恢复本波，不能要求再次观看。
- 广告加载失败、展示失败或提前关闭：不恢复波次、不消耗次数，保留失败结算。
- 广告播放期间切后台：以平台返回的完整观看结果为准；结果未知时不得发奖。
- 玩家缺少存活怪物王的硬克制卡：不提供失败续战广告。
- 失败源是普通怪或已可击杀的怪物王：允许提供续战。
- 第10波失败可以续战，成功后按广告辅助胜利处理。
- 恢复快照不得重抽商店、怪物王、凤凰或已结算奖励。
- 断网不影响单机战斗；没有可用广告时始终允许正常结束和新开一局。

## MVP 与延后内容

### MVP

- 每局一次“命运重整”激励广告。
- 波起点权威快照、同预算普通怪重整、王与凤凰冻结。
- 缺少硬克制卡时禁止无效广告。
- 广告奖励幂等、崩溃恢复、辅助胜利标记和排行榜分流。
- 完整广告漏斗与体验护栏埋点。
- 零强制插屏、零战斗内广告、零广告金币礼包。

### 延后

- 战后图鉴整理、商队改运的独立A/B测试。
- 基于广告填充率和玩家分群调整展示资格，但不能突破每局硬上限。
- 广告收入看板、远程关闭广告位和异常熔断。

## 验收标准

### 可自动测试

1. 同一局完整领取失败续战广告后，第二次失败不再显示续战广告。
2. 提前关闭、加载失败或展示失败均不发奖励、不消耗次数。
3. 重复发送同一广告完成回调任意次数只恢复一次本波。
4. 恢复后的主城、建筑、资源、卡牌、人口、科技和冷却与原波起点快照一致。
5. 重整前后普通怪威胁预算完全相等，普通怪编成哈希不同。
6. 重整前后怪物王是否出现、数量、种类和克制需求完全一致。
7. 重整前后黄金凤凰计划与奖励事务完全一致，不能重复生成或发奖。
8. 玩家缺少存活王的硬克制卡时不显示续战广告。
9. 广告辅助胜利使 `clear_count` 增加1，但不能覆盖纯净竞技最佳成绩。
10. 关闭网络或广告无填充时，玩家仍可结束本局并立即开始新局。
11. 延后广告位即使全部开启，每局已领奖广告数也不能超过2，展示间隔不少于120秒。

### 可观察试玩验收

1. 玩家在点击前能复述奖励是“重打本波并刷新普通怪”，不是复活当前帧或刷新怪物王。
2. 玩家能看见并轻松选择不看广告的正常结束路径。
3. 看完广告的玩家能理解怪物王为何没有改变。
4. 因缺少克制卡失败的玩家不会收到无效续战诱导。
5. 广告后立即退出率、次日留存和平均单局时长没有超过版本基线的预设负向阈值；未取得足量数据前不启用第二广告位。

## 风险与待验证假设

- 一次续战可能显著抬高总体通关率；纯净与辅助通关率必须分开调平。
- 同预算普通怪仍可能因克制关系产生巨大难度差，需监控重整前后理论有效生命和到城时间。
- 失败广告价值很高，但只覆盖失败玩家；成功玩家的变现需等待局外图鉴系统成型后再测试。
- 商店免费刷新会影响构筑、王之对策获取和排行公平，因此不进入MVP。
- 每局两次广告是硬上限而非收入目标；若留存或退出率恶化，应关闭低价值广告位而不是提高奖励强迫观看。
- Godot导出到微信小游戏后的广告桥接、生命周期回调和存档原子性需要单独技术验证。
