# 系统 GDD：兵营守卫与近战拦截

> 版本：0.1
> 状态：Godot灰盒通过，正式移动表现与微信触控待复核
> 权威范围：兵营建造、人口岗位、守卫生成、单体拦截和近战互攻

## 目标与游戏支柱

让人口不只决定资源产出，也能直接转化为前线兵力。兵营用可损失的守卫延缓敌人并造成稳定伤害，与箭塔输出和城墙承伤形成基础防线组合。

## 玩家动词与核心循环

取得兵营卡 → 战斗中拖到兵营格 → 支付材料 → 为兵营分配0～2人口 → 每个岗位生成一名守卫 → 守卫各拦截一名尚未越过防线的地面敌人 → 双方近战直至一方死亡 → 空闲守卫继续拦截下一名敌人。

## 规则、状态和转换

- 兵营卡只允许放入独立兵营格；聚落格、箭塔格和屏障格均拒绝。
- 兵营建造消耗55木材、20石材和10铁矿，提供2个岗位。
- 每个已分配岗位在怪潮中生成1名满生命守卫，最多2名；0岗位时没有守卫。
- 每名守卫同时最多拦截1名敌人，每名敌人同时最多被1名守卫拦截。
- 只拦截尚未越过守卫防线的敌人；不能把身后的敌人拉回。
- 被拦截敌人停止前进并攻击守卫。守卫死亡后，该敌人依次寻找空闲守卫、前方城墙和主城。
- 被拦截敌人死亡后，守卫释放目标并按稳定生成顺序拦截下一名合法敌人。
- 波次结束时守卫消失；下一波按当时岗位数满生命重新生成。兵营本体跨波保留。

## 公式、单位与算例

守卫与敌人共用物理伤害公式：

```text
有效护甲 = max(0, 目标护甲 - 穿甲)
最终伤害 = max(1, floor(基础伤害 × 100 / (100 + 有效护甲) × 克制倍率))
```

守卫攻击无甲野狼：`floor(8 × 100 / 100 × 1.0) = 8`。野狼攻击5护甲守卫：`floor(8 × 100 / 105 × 1.0) = 7`。

## 数据与可调参数

| 参数 | 默认值 | 说明 |
|---|---:|---|
| 兵营造价 | 55木+20石+10铁 | 沿用核心系统基线 |
| 兵营岗位 | 2 | 每岗位对应1名守卫 |
| 守卫生命 | 90 | 每波满生命生成 |
| 守卫护甲 | 5 | 野狼单击造成7伤害 |
| 守卫基础伤害 | 8 | 对野狼为中性倍率 |
| 守卫攻击间隔 | 0.9秒 | 与野狼相同 |
| 单守卫阻挡数 | 1 | 灰盒固定值 |

## 输入、反馈与无障碍

- 兵营格始终用文字说明合法卡牌；建成后显示“守卫 当前数/岗位数”。
- 守卫与野狼使用不同颜色和轮廓，并显示独立生命条。
- 建造资源不足沿用缺口弹窗，不只用颜色表达失败。
- 点击兵营格作为拖放的键鼠备用输入。

## 跨系统接口与依赖

- `RunCardInventory`提供兵营卡实例，主场景持有建造命令和原子扣费。
- `WaveEconomy`持有兵营岗位数，并把分配结果传给兵营实体。
- `Barracks`持有守卫名单，不决定敌人选择顺序。
- `WaveController`按稳定顺序配对空闲守卫和合法敌人，并在目标死亡后重新分配。
- `EnemyActor`持有当前目标状态；优先级为已配对守卫，其次前方城墙，最后主城。

## 边界条件与失败恢复

- 资源不足、格位占用、错误卡牌、重复释放或无效库存引用全部原子失败。
- 敌人已经越过守卫横坐标时，不参与新的拦截分配。
- 守卫和敌人在同一物理步死亡时，以先完成的伤害结算为准，死亡实体不再攻击。
- 重置清空兵营、守卫、配对关系和岗位项，不保留本局战斗状态。
- 暂停、存档恢复和远程敌人的特殊拦截留待对应系统实现。

## MVP 与延后内容

MVP包含一个兵营格、两名固定站位守卫、单体拦截、双方近战、岗位启停和文字反馈。延后兵营本体受击、守卫移动追击、升级、治疗、动画、音效和多路线寻路。

## 验收标准

1. 兵营卡只接受兵营格，成功建造精确扣费并消耗手牌；失败保持原状态。
2. 兵营提供2个岗位，每个已分配人口生成1名守卫；守卫属性为90生命、5护甲、8伤害和0.9秒间隔。
3. 两名守卫最多同时拦截两名尚未越过防线的野狼，配对稳定且不拉回身后敌人。
4. 守卫攻击野狼单次8伤害，野狼攻击守卫单次7伤害，双方生命变化可观察。
5. 一方死亡后解除配对；存活守卫可接敌，失去守卫的野狼继续寻找城墙或主城。
6. 波末清除守卫，下一波按岗位满生命重生；重置清空兵营和岗位。
7. 既有城墙、箭塔、经济、商店和波次回归继续通过。

## 风险与待验证假设

- 兵营与箭塔同时自动优先分配人口，可能让经济岗位长期缺人，需要后续观察玩家是否理解岗位顺序。
- 单守卫阻挡1名敌人易读但可能在大怪潮中过弱，后续可通过科技提高阻挡数而非直接提高伤害。
- 固定站位只适合当前单路线灰盒；正式多路线需要独立导航和拦截点系统。
