# 系统 GDD：资源建筑持续生产

> 版本：0.1
> 状态：规则已批准，数值待灰盒验证
> 权威范围：资源建筑按秒生产、岗位倍率、整数入账、暂停边界与资源不足反馈

## 目标与游戏支柱

资源建筑建成后立即体现经营收益，让玩家在60分钟连续守城中看到资源持续增长。生产仍与人口岗位绑定，避免建筑落地后无条件产生无限收益。

## 玩家动词与核心循环

建造资源建筑 → 自动或手动分配岗位 → 每秒观察资源增长 → 用新增资源继续建造、刷新或调整防线。

## 规则、状态和转换

- 资源建筑成功建成并至少分配1名工人后立即开始累计产出，不等待波次结束。
- `DAY_SETUP`、`WAVE_COMBAT`和`WAVE_RESULT`均可生产；`BOOT`、`RUN_LOST`和`RUN_WON`停止生产。
- 暂停或切后台冻结游戏时间，因此不累计生产。
- 岗位调整立即改变后续产速；已累计但不足1单位的小数进度保留。
- `WAVE_COMBAT`中点击地图内具体岗位建筑打开上下文面板，增减该建筑岗位或恢复自动分配；商店不再承载岗位列表。人口与单建筑容量校验不变，调整立即同步到农民和建筑。
- 波末不再结算建筑产出，只处理人口食物消耗、饥饿和结算记录，避免重复发放。
- 建造资源不足时不扣资源、不消耗卡牌、不占用格位，并弹出缺口明细。

## 公式、单位与算例

```text
实际每秒产速 = 基础每秒产速 × 已分配岗位 / 岗位上限
累计进度(t + Δt) = 累计进度(t) + 实际每秒产速 × Δt
本次入账 = floor(累计进度)
剩余进度 = 累计进度 - 本次入账
```

算例：金矿基础1金币/秒、岗位2。分配1人时产速为0.5金币/秒，第1秒不入账但保留0.5进度，第2秒累计到1并入账1金币。

## 数据与可调参数

| 建筑 | 满岗位基础产速 | 岗位 |
|---|---:|---:|
| 伐木场 | 2木材/秒 | 2 |
| 农场 | 2食物/秒 | 2 |
| 金矿场 | 1金币/秒 | 2 |

首轮建议范围：基础资源1～3单位/秒，金币0.5～1.5单位/秒。数值全部写入卡牌资源数据。

## 输入、反馈与无障碍

- 顶部资源栏每次整数入账后立即刷新。
- 建筑继续显示岗位人数；0岗位时不生产。
- 资源不足弹窗必须显示建筑名、缺少的资源名称与差额，并提供不小于44×44逻辑像素的关闭按钮。
- 缺口不能只靠颜色表达。

## 跨系统接口与依赖

- 卡牌数据提供`production_resource`和`production_per_second`。
- 岗位系统提供每座建筑当前岗位数；持续经济系统拥有小数累计进度。
- `RunEconomy`负责整数余额与原子扣费，UI不持有真实余额。
- 波次结算不读取持续生产累计值，只消费人口食物并记录结果。

## 边界条件与失败恢复

- `delta <= 0`、无岗位、无产出资源或建筑失效时不累计。
- 同一帧多个建筑的同种资源先聚合后一次入账。
- 重置、胜利或失败清空小数累计进度，防止跨局带出。
- 资源恰好足够时允许建造，余额可降为0且不会弹窗。
- 资源不足弹窗关闭后原卡仍可再次尝试。

## MVP 与延后内容

MVP实现伐木场、农场和金矿场持续生产、岗位倍率、暂停边界、整数累计与资源不足弹窗。延后内容包括资源飘字、建筑动画、科技倍率、饥饿减产和多个同类建筑。

## 验收标准

1. 三种资源建筑在白天建成并获得岗位后，无需进入战斗即可按秒增加对应资源。
2. 满岗位伐木场、农场和金矿每秒分别产生2木、2食、1金。
3. 半岗位按50%速率累计，小数进度不会因帧边界丢失。
4. 波末结算不再追加建筑产出，但仍消费人口食物且保持幂等。
5. 暂停和非活动对局阶段不生产，重置清空累计进度。
6. 资源不足时弹窗显示缺少资源及差额，余额、卡牌与格位保持不变。

## 风险与待验证假设

- 按秒产出会显著提高玩家停留收益，需用实际单局时长重新校准卡价和刷新费用。
- 顶栏频繁变化可能造成视觉噪声，后续可聚合为每秒一次动画而不改变底层结算。
