## 1. 推荐结论与范围

采用**关卡定义 + 可复用地形组件库 + 统一玩法编译 + 连续地表渲染**。策划用组件组装地形，建筑和单位共享同一地图规则，渲染系统负责材质、过渡、遮挡与缩远细节。关卡不是一张图片；组件也不是只附带透明边的 PNG。

`generate2dmap` 管线选 `scene_mode`，视觉为 `layered_raster`，运行对象为 `y_sorted_props + interactive_scene_objects + scene_hooks`；碰撞为明确形状及编译后的项目原生网格/通行边，区域为 `trigger_zones`，引擎为 Godot 项目原生方案。借用 `room_chunk_mode` 的接口与接缝验证合同，但不把开放建城地图强制切成封闭房间。36 世界像素网格继续决定建造与路径，视觉分块大小独立。

| 选择 | 适用与代价 | 本项目决策 |
|---|---|---|
| 固定整图 + 手工补碰撞 | 单张展示图快，改地形要连带修图、导航和遮挡 | 仅保留现有关卡兼容与概念参考 |
| 全部36格小图块 | 编辑直观，但高清山体容易像棋盘，方向和转角素材数量高 | 局部可用 TileMapLayer，不要求整体重建为小图块 |
| 连续地表 + 中型地形组件 + 独立物件 | 可换布局、保留自然轮廓，需要接口和编译工具 | 推荐，先做小样区验证 |
| 全三维地形 | 高度与遮挡自然，但引擎、美术、单位、光照与性能管线改动大 | 当前不采用 |

本轮交付设计与素材规格，不批量生成图片或替换运行地图。第一阶段仍是手工编排的固定关卡；随机地形、无限地图、关卡解锁、跨关奖励、战役连续继承均另行设计。

## 3. 关卡作为内容单元

当前关卡逻辑登记为 `level_001`，兼容实现标记 `legacy_dawn_wide_v3`。未来 `level_002`、`level_003` 为不同关卡定义，复用地图运行器；具体布局、数量与生态不作发布承诺。

每次新开关卡仍从统一初始人口、资源和卡牌规则建立60分钟对局；选关不等于解锁永久数值成长，通关不自动继承建筑、人口或手牌。

每关至少交付：关卡身份/版本、世界与边界、组件实例、地形与层级、主城/资源/出生区域、镜头档案、小地图、依赖与验证报告。布局差异要能产生扩张与防守选择，例如资源距城路程、峡口数量与绕行代价，而不只是换草色。

| 内容层 | 负责什么 | 不负责什么 |
|---|---|---|
| LevelDefinition | 当前关的组件位置、组合、资源与出生配置 | 通用寻路算法与卡牌消费 |
| TerrainModuleDefinition | 可复用地形及局部规则、接口、视觉引用 | 全局金币、计时与对局单例 |
| MapRuntime | 合成规则、占用、查询、注册和销毁 | 修改共享源资源 |
| BiomeStyleProfile | 统一材质、调色、照明、过渡风格 | 改单位速度和敌人奖励 |
| CameraProfile | 可玩区、可渲染区、操作与总览行为 | 改地形坐标和建筑占格 |

关卡编辑保存为 Godot `.tres/.tscn`；工具导出只读 JSON 为校验和运行快照，不允许两份同时手工修改。现有JSON通过兼容适配器读取，完成迁移后再逐项退役。

## 4. 像零件一样组装：组件分四类

| 类别 | 组件示例 | 内容及约束 |
|---|---|---|
| 连续材质 | 草、土、水、岩面 | 共享细节纹理 + 低频色场 + 区域权重；没有每块独立调色 |
| 结构地形 | 湖、岸段、崖段、草台、坡道/石梯 | 自带边界、局部玩法形状、层级、连接口与贴合边；中型轮廓优先 |
| 物件场景 | 林簇、矿点、巨石、桥或遗迹 | 脚点、占地、独立状态、遮挡策略；桥只在后续规则批准后生产 |
| 玩法标记 | 出生区、入口、资源槽、主城位、禁建带 | 编辑器可视化，运行不画成贴图，关联稳定实例ID |

推荐结构组件以8×8、16×16、32×16逻辑格作为初始包络模板，分别对应288×288、576×576、1152×576世界范围；形状可不规则，模板不是碰撞矩形。大型山体由崖段、转角、台面、坡脚与台阶组合，不能给每个山体重画整张地图。湖泊由闭合水域多边形、岸线样条及适配岸段组成。

小样区可用64×40格（2304×1440世界单位），同时覆盖平原建造、林缘、湖岸、双层台地和一条双向石梯。它是编辑器/测试场景，不是把第一关缩小后的成品。

### 每个组件必须附带的合同

- `module_id/version/style_profile`；永久源ID与关卡实例ID分开。
- `local_origin/anchor/nominal_bounds/visual_bounds`，局部坐标以世界单位记录；地面形状不是PNG像素。
- `allowed_transforms`，默认只允许整数格平移、scale=1、rotation=0；有方向光的图不能任意旋转或镜像。南向与北向崖面需要各自美术变体。
- `terrain_regions`：语义、可走、可建、代价、层级、资源标签；美术alpha不决定这些属性。
- `sockets`：接口位置/朝向/宽度/类型/上下层级、走廊多边形、视觉接缝带、是否允许封路；只在明确接口连接。
- `render_parts`：地面、接触影、崖面/树干、遮挡、装饰、低细节版本；每部分都有锚点和素材密度。
- `occlusionClass/actorSafeArea/occupantPolicy`，高物件采用局部淡化/轮廓等显式策略，默认不启用旧版整簇树林透明。
- `validation_points`：可走/禁行、可建/禁建样点及预期双向连接；测试样点要落在实际画面位置。

组件注册时只向父级提供数据和可渲染部分；不通过硬编码`../../Main`访问游戏，不自行扣资源、生成怪潮或开启全局计时。

编辑器操作顺序：新建关卡定义 → 选风格与边界 → 拖入结构组件并吸附格 → 对接道路/石梯端口 → 指定资源槽/主城/出生区 → 打开可走/可建/层级叠加 → 预览操作/总览镜头 → 一键验证并导出。错误定位到具体组件实例和端口，不让美术人员手改大JSON。

建议场景职责（未来结构，不是现有节点）：

```text
LevelEditorScene
  ModuleInstances          独立.tscn的编辑组织与局部数据
  GameplayMarkers          主城/资源/出生/接口，运行不画
MapRuntime
  GroundRenderer           共享材质与地表权重
  GroundAttachments        地基/接触影/低矮地物
  SortDomain               建筑/树干/单位统一脚点排序代理
  OcclusionParts           局部崖缘/树冠与可读性策略
  BoundaryScenery          外延景观
  DebugOverlay             只在编辑/调试显示
HUD                        复用现有独立界面
```

编辑组织和运行渲染组织可不同：组件实例拥有源数据与生命周期，排序代理只读其变换并跟随删除；禁止为了跨组件Y排序复制两份权威状态。

## 5. 组装数据与统一玩法编译

建议数据结构（示意字段，不是当前可加载格式）：

```yaml
schema_version: 2
level_id: level_001
revision: 1
style_profile: moonlit_hd_v2
cell_size: 36
world_rect: [0, 0, 7056, 2880]
module_instances:
  - instance_id: plateau_east_01
    module_id: terrace_two_level_a
    module_version: 1
    origin_cell: [136, 16]
    variant: south_facing
connections:
  - from: plateau_east_01.lower_road
    to: plain_central.east_road
resource_slots: []
spawn_zones: []
camera_profile: campaign_operation_and_overview
```

上例省略了平原实例和端口细节，不能直接用于运行验收；完整关卡不得存在悬空引用。编辑器保存时执行：

1. 验证ID、版本、路径、格对齐、允许变换、整体边界和生态风格。
2. 变换局部多边形/端口/脚点到世界坐标；对齐接口并检查宽度、方向及层级，通路缩进须考虑单位半径。
3. 合成单一语义地形场，计算逻辑格和显式通行边，再注册资源占地、禁建与交互入口。
4. 导出可视渲染清单、网格、连接图、小地图与哈希；运行器加载同一版本产物。
5. 新局另建占用、资源claim、单位与事件状态；共享`.tres`保持只读。重开/换关清空路径与出生缓存、信号和异步请求。

冲突规则不依赖节点树顺序：不兼容结构重叠直接报错；水、硬崖、边界保持阻挡，不能被普通道路覆盖；跨层只准由明确坡道/石梯接口开放。美术过渡带可以重叠，玩法通行必须唯一。每格含`terrain/elevation/walkable/buildable/move_cost/resource_slot`；静态建筑占用与动态单位单独保存。

首阶段继续单层XY格加明确跨层边，禁止同一XY同时有可走桥面与桥下道路；需要真正叠层时另设计三维节点键。36格过粗导致窄台阶不通时，先加宽地形或修组件，不允许用隐藏穿崖边放行；更精细导航需要独立验证。

### 实现需改造的实际入口

`map_definition.gd`由常量单例演进为关卡实例；`map_layout.gd`、`GridMapModel`、`TerrainMapData`和山路数据读取注入实例；`GridPathfinder`缓存键包括关卡实例、地形版本和占用版本；`main.gd`的资源注册、出生、镜头、遮挡、小地图、拖牌统一读`MapRuntime`。

草地shader的`map_size`、全局遮罩原点、源图坐标转换、`MapDropSurface`的屏幕反变换也是迁移检查项，不能只改一个JSON路径。先用兼容入口保持旧测试，再逐步加入新关卡夹具。

## 6. 野怪、攻守地形与关卡机制

地形首先影响**走哪里、在哪里建、资源运输多远、有哪些防守入口**。这已经能产生攻守选择；高地增伤、视野迷雾、弹道遮挡、道路加速、水上战斗和天气伤害均未获批准，默认关闭。

出生从常量点演进为 `SpawnZone`：多边形、层级、合法入口、方向标签、单位通行类别、权重、启用时间、确定性种子和到城通路要求。波次系统决定怪种与威胁预算，关卡仅提供合法出生候选，不额外复制怪潮和奖励逻辑。

候选流程：在区域中采样 → 检查完整单位落脚范围、地形/层级/占用 → 检查到城合法路线或可摧毁封路目标 → 成功才实例化。最多尝试16个候选/请求为小样初值，失败跨帧重试；不能每帧无限寻路或丢弃威胁预算。永久水/岩完全隔绝的区域在离线检查时报错，玩家墙体封路则沿用可破坏阻挡规则。

镜头视野不是出生可达性的依据；切镜头不能刷掉怪或改变可用区域。以后若采用屏外出生，只能作为可关闭的表现偏好，所有候选都在屏内时必须使用预告等可复现回退，不能延迟到玩家无法获得金币。

每关输出地形设计表：主城安全展开面、进攻入口、主/备路线、峡口宽度、资源运输距离、可防守面积与退路。以“近资源但多入口”和“远资源但可守峡口”等组合设计差异，不能承诺靠单个高地就稳胜。

资源行走与经济一起量测：往返时间=`往返实际路径长度/单位速度 + 采集/交付时间`。第一关迁移保留四林两石两铁ID、已验证八石梯、S6和分叉连接；如果调整它们，必须作为关卡改版单列路线与运输差异，不用改速度掩盖扩大距离。

## 7. 无缝组装的美术工程规则

避免“拼贴感”需要同时控制几何、材质、明暗和细节密度；扩大模糊羽化无法补救两块完全不同的草或错误层级。

1. **统一基础材质**：平原、山台、林缘使用同一草材质家族，世界坐标采样不在组件原点重启；叠低频色场与地形权重，避免独立大图各自带明暗。草叶、岩缝的尺度与建筑按密度档案一致。
2. **自然边界组件**：湖岸有水域、湿土/砾石、草缘三段；山体有草台、崖唇、崖面、坡脚四段。连续闭合岸线、凸凹角、端头和三向交会都要有覆盖，不能只做直段。
3. **过渡宽度按地形定义**：草土/坡脚先试18～72世界单位；它是可调美术带，不改变可走格。透明过渡不准覆盖另一层的硬崖或“羽化出一条假路”。
4. **无重复投影**：环境光与主光方向统一；接触影归结构组件，建筑影归建筑。连接处的接触阴影只绘制一次，禁止两张重叠边一起变黑。
5. **纹理隔离和mipmap**：图集边缘先扩色，预留足够隔离像素；跨多级mipmap要单独验证。大结构优先独立纹理或独立mipmap页，不能把固定2像素隔离当所有缩放都安全。
6. **按语义拼接，再做装饰**：草簇/碎石可以破轮廓，但不能靠一排树藏住错误接口。变体由固定种子选择，换镜头不跳变；不随机旋转带方向光的山壁。
7. **接缝双重检查**：调试视图显示格与接口；正式视图关闭标记，以真实镜头检查色带、重复岩纹、矩形边、透明黑边和假通路。数值边缘差只能辅助，不代替人眼。

草地风动使用独立叶层与语义控制遮罩，避免把土、水和岩壁扭动；全局风场共享，组件边界连续，暂停冻结、重开恢复。当前尚未实现，旧单草簇GIF不作为覆盖全图的方案。

## 8. 建筑摆放与落地

继续36格权威占地：塔/墙1×1、一般建筑2×2、主城4×4；主体可越出占格，逻辑占地、点击范围、脚点、投影范围四者分别定义，不能用PNG矩形当碰撞。

建筑落地包包含：主体、脚点/地面接触线、材质适配底座、接触影、可选投影、装饰清理遮罩和交互入口。先支持草/土两种适配；矿场结合资源点底座，农场使用耕地；不为每个关卡重新画同一栋房子。

底座是世界地表中的局部材质混合：硬地基在占地附近，外圈渐疏草/碎石采样本地地表色；大型底座的装饰边可能超出占格，但不能遮住相邻建筑落点、单位、湖岸和台阶。仅在明确的land/level兼容区绘制底座，不能跨层把崖面铺成院子。拆除恢复原地表权重与植被，重叠底座按实例重算并限制累计暗化，禁止直接擦改共享PNG。

预览和落地共用同一查询：完整占地内地形允许、同层、无静态/动态占用、资源类型匹配；山区岗位建筑沿用60世界单位内合法入口要求，入口路径不得隔水/岩交互。预览只表达结果，最终提交再校验并原子扣牌扣材料；失败说明原因且保卡保材料。

维持已有自由城墙策略，允许玩家封路后触发敌人破障，不在新管线中悄悄改成“所有封路建筑禁建”。平台换层边和特殊入口的永久禁建区必须在关卡定义中明确，并让预览显示。

地表/底座/接触影固定在地面层；建筑、树干、单位的排序代理注册进同一个公共Y排序域。组件虽然独立编辑，不能每个父节点独立排序导致跨组件遮挡失效。复杂山壁/树冠拆为局部遮挡片；不能把整座山放在高Z永久盖住人。单位头肩、动作、选中与路径提示需保持可读，建筑屋顶点击岗位延续。

## 9. 镜头、视口与“缩远露图”

地图显示和输入继续限定在顶栏实际下缘到手牌实际上缘的矩形 `P`，常态960×540战斗布局约960×391；不能用整窗口960×540代替。开店不改变世界尺寸，HUD遮挡区域应拦截输入；隐藏手牌、改变UI缩放、调整窗口和暂停平移都要刷新同一矩形。

定义三种不同范围：`playable_bounds`决定规则，`camera_bounds`决定操作镜头覆盖，`render_bounds`保证镜头内有完整景观。外围山林/远水为禁行禁建景观，不增加可采资源；可玩区边界要通过自然地貌和建造预览表达。

**建议普通操作与全图总览分开：**

- 操作镜头：滚轮到 `z_cover=max(P宽/镜头边界宽,P高/镜头边界高)` 后停止，最大倍率保留1.6；以鼠标为锚点并在最后限位，视口持续由地形填满。默认0.72（若低于cover则提高），回主城沿用。外围有延续景观时可将camera_bounds放宽，但render_bounds必须包含所有可见矩形。
- 总览镜头：由现有“全图”入口进入，`z_fit=min(P宽/可玩区宽,P高/可玩区高)`，地图完整等比显示；多出的画面由单独的景观背景/总览面板填充，不暴露裸画布。总览用于定位，建议点击定位并回操作镜头；拖牌时返回可准确放置的操作倍率。这是新的交互提案，现有全图仍使用原行为。
- 小地图：显示可玩区域、地形/资源符号、镜头框；鼠标到世界坐标考虑内部等比留边，不能直接按控件外框映射。

不同画幅无法同时满足“完整全图、无留边、无裁切、无变形”。推荐把完整全图限定在总览；如果希望普通滚轮始终可看全图，则需要接受外围景观出现在多余区域并为全部受支持画幅制作足够外延，不通过继续扩可玩区来凑长宽比。

以当前7056×2880和P=960×391计算：fit≈0.135764、cover≈0.136054，几乎无差。若P=960×540（仅算例，非当前4:3实测），fit≈0.136054、cover=0.1875，相差显著，说明不能写死最小倍率。

镜头中心限位：`可见半尺寸=P尺寸/(2z)`，中心范围为`camera_bounds最小值+半尺寸`至`最大值-半尺寸`；不可容纳时居中并使用总览逻辑。render_bounds还要覆盖高树、岩缘、投影和风动的外伸，不能只按地面脚点剔除。

### 2026-10-29 已授权的镜头体验补充

本轮用户授权实施：普通操作视距分布防0.54、建设0.82、近景1.40，均可配置且按当前地图cover下限与1.60上限夹取；开局和回主城使用建设档。全图继续使用实际可玩视口的fit，进入前记住操作位置与倍率，再次点击总览或M返回；小地图点选在目标区域进入可操作视距。快捷切换以约0.22秒平滑过渡，鼠标平移/滚轮立即接管，拖牌期间停止过渡。HUD独立，固定二维方向与现有地形占用不变。上述为本游戏的体验参数，不是《部落冲突》的内部相机参数；Story-034记录实施和证据。

## 10. 放大清晰、缩小稳定的分辨率合同

2026-10-29同日交互修订：用户要求去掉小地图所有按钮。当前小地图只显示地图、视野框和标记并支持点击定位；面板不留按钮空位。M总览往返、Home回城、滚轮连续缩放保持，三档参数仅留作相机配置与验证接口。上节快捷按钮方案已由本修订替代。

保留冷蓝月夜和暖金聚落，建议环境采用高清像素感、清晰块面与克制纹理；不再把所有美术降成36×36再放大。旧人物像素风保留，通过边缘、色彩和尺度校准融合。环境Linear+mipmap，原像素角色可保留Nearest；每类素材在真实镜头评审，不全局盲切过滤器。

设源有效像素宽度为`S`，覆盖世界宽为`W`，纹理密度`D=S/W`。设`k`为实际物理像素/逻辑视口单位，镜头倍率`z`，则：

```text
一个源纹素投到屏幕的物理像素 = k × z / D
避免源像素放大的最低条件：D ≥ k_max × z_max
```

4K窗口且canvas_items实际k=4、z=1.6时，最低密度6.4 texel/世界单位。现草地1448/216≈6.704，满足这条密度条件，不代表其他岩壁或建筑已经达标。高DPI系统缩放不能再机械乘一次，必须读实际渲染目标与变换。

建议环境生产密度8 texel/世界单位：256世界单位细节片需2048原生有效像素；512需4096，1152需9216，不宜整块绘制。因此组件是逻辑包络，内部可引用多片独立高清结构和共享材质。不能把生成的1K图插值为4K后宣称有4K细节。

若7056×2880全图都按6.4密度烘焙，需约45159×18432像素，RGBA8约3.10GiB，含完整mipmap约4.13GiB（不含CPU副本和其他素材）。这正是应共享材质与局部结构细节的原因；把巨大图切18片并不会减少全部常驻纹理总量。

缩远依赖mipmap、低对比细纹和装饰LOD：按投影像素大小切换近/中/远档，避免按固定缩放值忽略4K；草叶和小石远景淡出，山湖轮廓、资源符号和危险提示保留。采用约15%滞回区防反复切换；LOD不能关闭玩法碰撞或改变出生。mipmap缓解缩小噪点，不能创造放大细节。

## 11. 性能和加载预算（待实测校准）

以下为项目小样目标，不是通用行业硬指标；最低硬件尚未锁定，每份报告记录CPU/GPU/驱动、Godot版本、分辨率、渲染器、单位数、冷/热启动与采样时长。

| 项目 | 初始目标 | 测量与退路 |
|---|---|---|
| 基准帧率 | 1080p 60fps，帧预算16.67ms | 记录CPU/GPU帧P95/P99/最大值；4K单独报告，不能凭截图承诺60fps |
| 地图渲染 | 1080p地表/地物GPU P95≤4ms候选 | 先减重叠透明层、取样次数和远景细节；仍失败再改渲染结构 |
| 寻路调度 | 主线程每帧约2ms预算，暂停态预热；不再出现>50ms单次地图任务为候选门槛 | 小样先测；分批不改变最短路与封路规则，未达标报告失败 |
| 地图纹理 | 本关地图相关常驻纹理目标≤256MiB | 运行API可用时实测，另列理论估算；不把CPU静态内存当显存 |
| 纹理页 | 优先2048，4096例外需说明 | RGBA8+完整mip约21.33/85.33MiB，压缩支持和质量实测后再选 |
| 透明层 | 地表尽量不透明，过渡局部化 | 不在全屏叠多层高密度草、透明影和风层；用实测过绘定位 |
| 地图加载 | 加载完成且导航/出生校验后才开局；总时间记录 | 初版小关整关加载，纹理复用与可见剔除；达到实测瓶颈再做流式加载 |

现有地表配置阶段会加载全部片，只在绘制时裁可见片；这种行为不是流式加载。未来即便卸载远景视觉，也要保持全部玩法图、资源占用和敌人模拟；不能因为相机远离而停怪/停运输。未采用流式加载前不为此搭完整开放世界框架。

256MiB目标下的小样常驻分配示例：草地2页、土/岩/水各1页、岸崖台阶共2页、树林1页、底座1页，合计9张2048页约192MiB；低矮装饰1024页约5.33MiB，外围2048×1024页约10.67MiB，控制层暂留16MiB，总约224MiB，余约32MiB缓冲。结构按共享材质加小轮廓层组织；若实际成品无法放入此预算，必须减少同时驻留变体或申请新预算并实测，不能把各素材“单页预算”相加后仍声称小于256MiB。角色、建筑主体、HUD与渲染目标另列全应用预算。

## 12. 美术制作、资产范围与验收流程

关联[地图美术修订草案](../art/map-art-bible-v2-proposal.md)、[首批素材范围](../assets/map-kit-v2-production-plan.md)与[素材总表](../assets/asset-manifest.yaml)。旧美术圣经保留，修订草案通过后再合并，候选素材状态不自动升级。

生产顺序：先灰盒拓扑和实测镜头 → 统一一套草土岩水材质与光照 → 生成干净基础地表 → 用可见基础图作参考生成稀疏场景验证图 → 从验证图确认最多9类关键可见对象 → 独立制作结构/物件 → 组装样区 → 真实单位/建筑/镜头评审 → 第二种布局复用验证 → 再迁移第一关全图。

可见美术默认内置image_gen或复用合格现有素材；每个新素材保存手写提示词、原稿、原生有效尺寸、参考哈希和处理记录。脚本只负责切片、遮罩处理、拼装、导出与QC；不以程序绘制最终草、岩壁或湖岸。逻辑灰盒、编辑器标记和测试叠加可用程序形状。

基础地表不烘焙树、建筑、矿点、可复用巨石或其他独立对象；此次要求可移动湖/山，因此其结构也独立于通用草地底层。场景验证图仅指导生产，不作为运行背景，也不从完整概念图剪出最终结构组件。每次用生成图作下一轮参考时，先实际查看该图，再明确保留边界、比例和光照。

结构碰撞件、崖段、台阶、长岸线、树冠和建筑底座逐件/条带制作；只有小草簇等紧凑装饰可用方格图集。源图尺寸不足或接口走形时退回生产，不放宽QC伪装通过。

这是常见模块化场景、数据与表现分离、纹理密度预算、组件小样验证方法在本项目上的组合；没有统一“行业标准地图尺寸”或“通用256MiB标准”。所有预算和组件规格都需在本项目验证。

- [Godot图片导入](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_images.html)：过滤与mipmap配置的技术依据；不是图片重采样后有新细节的证明。
- [Godot多分辨率](https://docs.godotengine.org/en/stable/tutorials/rendering/multiple_resolutions.html)：基准尺寸与canvas_items拉伸；实际k仍按运行目标测量。
- [Godot CanvasItem](https://docs.godotengine.org/en/stable/classes/class_canvasitem.html)：Y排序、Z层与可见性基础；跨组件遮挡正确性需项目实测。
