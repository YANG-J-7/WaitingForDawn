# 月湖山谷 3D 地图与光影开发文档

版本 0.2 · 2026-11-06 · 开发提案

适用范围为《Waiting for Dawn》第一关 `level_001`。首个交付是独立的 Godot 可玩样区，验证真实地形高度、近景细节、地图交互和公共光源。整关迁移以样区验收为前提。本提案的模型规格、灯光方案与性能目标均待样区验证。

## 1. 当前运行基线

| 项目 | 现状 |
| --- | --- |
| 引擎 | Godot 4.7 Standard、GDScript、GL Compatibility，Windows 键鼠验证。正式入口为 `res://src/main/main.tscn`。 |
| 地图 | 月湖山谷为 7056×2880 世界单位，36 单位一格，共 196×80 格。地形画面使用 2D 图集，玩法独立读取 `GridMapModel`。 |
| 通路与资源 | 保有四林、两石、两铁，四处出生点、八条石梯及 S6 双段石梯。外围针叶树已有独立摆放。当前关卡隐藏资源树林的外观，保留资源点与建造接口。 |
| 镜头 | 布防 0.24、建设 0.36、最大近景 0.45。滚轮锚点缩放，小地图可点击定位，M 进入或退出总览，Home 回城。 |
| 光影 | 2D 公共点光随 60 分钟有效对局时间沿地图北缘由左向右移动，最后 5 分钟进入黎明。局部灯继续工作。关卡默认关闭全部运行时阴影，素材原有明暗保留在图像中。 |

项目依据见 [关卡资源](../../src/levels/level_001.tres)、[模块化地图方案](../../design/gdd/modular-level-map-system.md)、[网格 GDD](../../design/gdd/grid-map-rendering-system.md)、[地图 Story-033](../../production/stories/story-033-modular-level-map.md)、[镜头 Story-034](../../production/stories/story-034-camera-view-levels.md) 和 [光影 Story-035](../../production/stories/story-035-global-world-lighting.md)。

## 2. 场景与数据职责

采用固定斜俯视的正交 `Camera3D`。山地、湖岸、水面与树木在同一个 3D 世界中渲染，HUD 沿用 2D。首版角色和建筑可用脚点对齐的 `Sprite3D` 作为显示层，沿用现有单位与建筑状态，按近景效果决定哪些资产优先换成 3D 模型。

| 模块 | 职责 |
| --- | --- |
| `LevelDefinition` / `LevelMapRuntime` | 提供关卡边界、资源、出生点、地形与现有导航连接。由关卡配置关联候选 3D 表现场景。 |
| `GridMapModel` / `GridPathfinder` | 继续负责通行、跨层连接、占用、资源匹配和路径。沿用当前水平距离、速度、射程与建造规则。 |
| 3D 地表与高度查询 | 以可走表面提供平地、山台和石阶的脚点高度。崖壁、湖岸和水面提供点选边界，零散装饰使用独立的拾取层配置。 |
| 镜头与输入适配 | 统一可玩视口、屏幕射线、地图坐标与网格之间的转换。小地图和拖牌预览沿用相同的关卡坐标。 |
| 3D 光照控制 | 从 `RunState` 读取有效对局时间，输出环境色、主光与局部灯状态。调试预览使用独立的时间覆盖值。 |

首版可按 **1 逻辑格对应 1 个 3D 水平单位**制作灰盒。以关卡原点为基准，现有二维 `(x, y)` 映射到 `(x / 36, 地表高度, y / 36)`。美术模型与拾取表面采用相同的关卡坐标，石阶按连接编号关联实际踏面和平台。单位沿现有逻辑路径前进，再按所处通路采样高度。建筑底座对齐合法占地所在的平台，预览和确认落点都检查完整占地。

鼠标进入可玩视口后，从相机向场景发射射线。先处理最前方地表命中，再把位置映射回逻辑格，交给原建造校验。崖面或水面命中应直接拒绝，避免射线穿过去选中后方合法地块。建筑点选使用独立命中规则。缩放时以光标下的地面点作为锚点，按实际视口计算边界。镜头档位用可见范围和建筑屏幕高度校准，原来的 `0.24 / 0.36 / 0.45` 作为对照。 [Godot Camera3D](https://docs.godotengine.org/en/stable/classes/class_camera3d.html) · [Godot Sprite3D](https://docs.godotengine.org/en/stable/classes/class_sprite3d.html)

## 3. 地形、树林与动画制作

| 资产 | 建模与表现 | 近景检查 |
| --- | --- | --- |
| 山台、崖面、坡脚 | 先按现有地形与道路做分区网格。大轮廓由几何决定，细裂纹由共享材质表现。原地图可作为布局和色彩参照。 | 崖顶、侧壁和坡脚能读出高差，岩纹不过度重复，路面无悬空和拼缝。 |
| 石阶与山路 | 先做 S6 两段踏面及中间转向平台，沿用原有上下层连接。把可走踏面高度和装饰岩块分开。 | 双向通过时脚底持续贴地，从远景也能看清石阶入口。 |
| 湖盆、岸线与水面 | 独立水面网格贴合湖盆，使用浅深水颜色过渡、滚动法线和沿岸局部碎浪。用岸石与湿土解释水线。 | 水纹留在水域，水面与岩壁相接时无穿插和明显跳变。 |
| 边界树林 | 树木独立建模和摆放。每株树以树根为原点，按地表采样贴地，旋转、缩放及风动相位用稳定数据控制。密林可按区块和树种用 `MultiMeshInstance3D` 批量绘制。 | 检查平地、坡脚与高台根部。树梢随风，根部保持贴地。远景简化枝叶并保留林线。 |
| 资源树林 | 将资源点 ID、占地、伐木场吸附点和农民入口与树木外观分开。样区可以验证一处现有资源点的显示、占用与恢复。 | 树木疏密、淡出与模型细节切换均保持原有资源规则和通路。 |

近景加少量独立芦苇、碎石和草簇，优先放在岸边和林缘。水纹、草梢、树梢和火光错开相位，远景逐步减少小装饰。风动和水动画用统一的表现时间，暂停时冻结，恢复时续播，重开时按初值复位。重点检查树冠或岩缘挡住单位、建造预览和石阶入口的情况，必要时对挡住当前操作目标的局部植被做淡化。 [Godot 网格细节层级](https://docs.godotengine.org/en/stable/tutorials/3d/mesh_lod.html) · [Godot MultiMeshInstance3D](https://docs.godotengine.org/en/stable/classes/class_multimeshinstance3d.html)

灰盒可用 Godot 网格，正式结构与树木可由 Blender 制作并以 glTF 导入。每种资产记录版本、来源、尺寸、原点、材质、近远景版本及是否参与遮挡。样区先复用一套草、土、岩和水材质，减少跨区域色差与重复资源。

## 4. 公共光源、局部灯与阴影

### 主光按同一局时间驱动

- **全局环境光**由夜间冷色过渡到黎明暖色。沿用最后 300 秒的过渡区间，读取有效对局剩余时间。暂停冻结，重开复位，HUD 和小地图的可读性独立校验。预览支持拖动时间轴。
- **主光**在样区提供两个独立对照配置，每次启用一种。如果目标是保留现有「光池沿北缘移动」的观感，用 `OmniLight3D` 沿北缘移动并配置高度、范围和衰减。如果目标是全图统一的月光和晨光，用 `DirectionalLight3D` 随时间转动方向。方向光适合全图共用，移动节点坐标不会改变照射方向。用同一构图比较近远端亮度和背光面，再决定正式配置。 [Godot 3D 点光](https://docs.godotengine.org/en/stable/classes/class_omnilight3d.html) · [Godot 3D 方向光](https://docs.godotengine.org/en/stable/classes/class_directionallight3d.html)
- **局部灯**从一处主城火盆开始，使用短范围暖色 `OmniLight3D` 和轻微亮度变化。灯随主体显隐与销毁更新，首版默认关闭局部投影。密集建造时检查局部灯重叠与单网格受光预算。
- **材质受光**由表面方向和材质共同决定。新 3D 资产保留固有色，弱化固定来向的烘焙高光和暗面。临时 2D 立绘保留其已有明暗，避免重复调色造成过黑。湖面以法线、浅深色和有限高光表现；当前 GL Compatibility 下以可运行的材质效果为验收。 [Godot 渲染器能力表](https://docs.godotengine.org/en/stable/tutorials/rendering/renderers.html#environment-and-post-processing)

### 阴影分阶段验证

样区先对比「全关」「仅山崖与树林」「加入建筑和单位」三组，使用同一镜头、主光位置和材质。山崖、树木先用实际几何投影，检查影子落到坡脚、台阶和邻近地形时的连续性。建筑和单位等使用 2D 素材时，若需要投影，优先为代表对象测试简化的 3D 投影形体或单一脚底接触影。进入后一档前，确认影子贴根贴脚、叠加后道路仍可读，近景与布防视角均可辨认单位。正式阴影开关按样区结果决定，当前关卡继续以默认关闭作为对照基线。

## 5. 实施顺序与阶段出口

| 阶段 | 交付 | 通过条件 |
| --- | --- | --- |
| P0 · 灰盒样区 | 独立可运行的测试场景，包含可建平地、S6 双段石梯、一个山台、湖岸和针叶林缘。 | 建设和近景镜头构图成立，平地和山台的落点及可走路径与原地图可对照。 |
| P1 · 玩法接通 | 接入射线拾取、占地预览、合法建造、农民移动和小地图。 | 农民能双向走完 S6，单位和建筑贴地。水域、岩壁和已占用格拒绝建造，卡牌和材料正确保留。 |
| P2 · 美术与光影 | 交付草岩材质、水面动画、独立树林和光照对照。 | 保存建设档与近景对照，完成主光方案和阴影档位的观感、遮挡与帧时间复核。 |
| P3 · 第一关迁移 | 按平原、湖岸、山区、外围树林迁移整图，保留独立 2D 对照入口供回归。 | 校核八资源、四出生点、八处石梯与原有运输路线。整关完成真实输入、多画幅、压力和长局验证后，再决定默认场景切换。 |

## 6. 验收矩阵

| 检查项 | 测试方法与证据 |
| --- | --- |
| 通路与建造 | 对照原始格、可见踏面和拾取范围。记录 S6 上下坡双向路径，检查封梯后改道或停步，解除后恢复。覆盖 1×1、2×2、4×4，占用、临水、跨崖、错资源与失败保卡。整图迁移后复核矿点实际往返。 |
| 镜头与遮挡 | Windows 真实鼠标操作，覆盖锚点缩放、移动、M 往返、Home 回城、小地图定位、拖牌与窗口调整。保存 16:9、4:3、超宽与 4K 的总览和近景。对林缘与崖下目标记录遮挡前后效果。 |
| 光影与动画 | 在已用 0、30、55、60 分钟保存同镜头截图，追加暂停、恢复、重开和火盆销毁测试。记录移动点光与方向光对照、各阴影档位、湖岸水纹边界和树根贴合。 |
| 性能与稳定性 | 以 1080p 60 FPS、每帧 16.67 ms 为候选目标，记录主线程与 GPU 帧时间 P95、P99 和峰值，4K 单列。区分首次寻路、局部灯与阴影成本，比较同镜头各档，另测密林近景与多单位同时寻路。正式迁移后记录一次自然长局和重开。 |

建议在开发时把样区做成一条可重复运行的链路，从选中石阶附近的地面开始，完成一次合法拖牌、观察农民往返，再拖动光照时间轴。灰盒验收先看地形和操作，材质接入后再评近景与光影。每阶段保存可复现步骤、实景截图和测量条件，阶段验收与整关验收分别记录。

## 7. 可用 Codex 技能与调用顺序

| 阶段 | 技能 | 在月湖山谷的用法 |
| --- | --- | --- |
| P0 · 灰盒样区 | `$gs-prototype` | 建立独立 Godot 预览，先验证山台、S6 石梯、湖岸、针叶林缘和固定斜俯视镜头。 |
| P0–P2 · 技术决策 | `$gs-architecture-decision` | 记录 3D 地形与 2D 网格的职责、拾取与高度采样约定。主光类型和正式阴影档位按样区对照结果记录。 |
| P1–P3 · 拆分与实施 | `$gs-create-stories`、`$implement-game-story` | 先拆出拾取与拖牌、单位贴地、材质与树林、主光与阴影、整关迁移等 Story，再按依赖逐项实现，记录验收证据。 |
| P2 · 美术资产规格 | `$plan-game-assets` | 为崖段、石阶、岸石、针叶树、草簇和水材质登记规格，明确尺寸、原点、材质、近远景版本、动画和投影需求。 |
| P2 · 参考图与纹理 | `$generate2dmap`、`$generate-game-asset` | 前者辅助制作山湖构图和林缘风格参考，后者制作草岩纹理、水纹和树木贴图候选。实际 3D 网格由 Godot 灰盒或 Blender 建模交付。 |
| P1–P3 · 阶段验收 | `$run-game-qa` | 按第 6 节检查通路与建造、真实鼠标与多画幅、光影开关、暂停和重开，并记录帧时间与复现步骤。 |

先用 `$gs-prototype` 跑通样区。进入玩法接入前记录坐标和拾取约定，再按 Story 实施。美术与光影阶段先定资产规格，再按需要补参考图和纹理。每阶段交付后使用 `$run-game-qa` 复核。

P0 可直接使用这条指令。

> `$gs-prototype` 按《月湖山谷 3D 地图与光影开发文档》的 P0 范围，做一个独立可运行的 Godot 灰盒样区，包含可建平地、S6 双段石梯、山台、湖岸和针叶林缘。用固定斜俯视正交镜头检查建设档与近景档，并对照现有 2D 网格的落点和通路。
