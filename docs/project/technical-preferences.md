# Waiting for Dawn 技术偏好

> 版本：0.2
> 更新：2026-09-14
> 阶段：制作阶段，Steam 单机方向调整

## 引擎与语言

- 当前开发引擎：Godot 4.7 Standard。
- 主要语言：带静态类型标注的 GDScript。
- 核心玩法继续使用 GDScript；新增原生扩展或平台插件前需要独立技术验证与版本固定。
- 桌面导出时编辑器与导出模板需匹配，不再受微信 WASM 模板版本约束。

当前基线以 [ADR-0002](../architecture/adr-0002-steam-single-player-baseline.md) 为准；原 ADR-0001 已由新决议替代。现有灰盒与测试使用 Godot 4.7，Steam 交付尚未验证。

## 平台与渲染

- 开发平台：Windows。
- 发行目标：Steam 单机。Windows 为暂定验证平台，正式支持的操作系统清单待定。
- 画面方向：横屏。
- 逻辑分辨率：960×540，使用 `canvas_items` 拉伸。
- 渲染器：GL Compatibility，避免依赖Forward+特性。
- 2D物理：Godot Physics 2D，固定60Hz。
- 输入：以键鼠为后续设计基线，已有滚轮缩放、中键平移与鼠标拖牌；游戏快捷键与重绑定待规划。保留已有触控，不将其作为 Steam 当前门槛。
- 像素素材默认最近邻采样，不依赖高分辨率纹理缩放。

## 项目结构与命名

```text
src/core/       全局状态、事件和纯规则
src/main/       入口与场景编排
src/gameplay/   后续战斗、敌人、建筑和波次代码
src/ui/         后续界面代码
assets/         后续正式素材与数据
tests/          自动化测试
tools/          本地检查和构建脚本
```

- 文件与目录使用 `snake_case`。
- GDScript类使用 `PascalCase`，变量、信号与函数使用 `snake_case`。
- UI不持有权威战斗状态；全局状态和各系统通过命令、信号交互。
- 数值规则优先数据化，场景脚本不写死卡牌、敌人和波次完整配置。

## 性能与体量预算

这些是原型预算，不是平台上限：

- 目标帧率60 FPS；低端机允许稳定降至30 FPS，不允许逻辑速度变化。
- 同屏普通敌人MVP软上限80，投射物软上限160。
- 单张像素纹理优先不超过1024×1024，正式资产进入共享图集。
- 原微信8 MB内容包预算停止作为发布约束；正式桌面包体和最低配置待测量制定。
- 首次可交互3秒以内保留为待测原型目标，需在暂定Windows验证环境记录。
- 禁止在每帧创建大量节点、字符串或临时数组；生成器和投射物使用对象池候选方案。

## 测试策略

当前 Windows 开发与回归使用 Godot 4.7 Standard，已有命令行环境。执行 `godot --headless --editor --quit --path .` 注册新类，然后用 `tools/run_tests.ps1 -GodotPath <本机路径>` 跑相关测试。

- 使用 `tools/check_project.ps1` 做结构与配置冒烟检查。
- 桌面发布需另验干净环境启动、离线完整对局、多分辨率和存档读写；当前未完成这些验收。
- 纯公式与状态转换优先写成无场景依赖的GDScript并增加headless测试。
- 本地存档与可选平台服务分离；是否接入 Steam 成就、云存档和在线排行待定。

## 依赖与禁用模式

- 首个灰盒不引入第三方插件。
- 后续平台插件必须在独立技术验证后固定版本和校验值，不能跟随浮动最新版。
- 不允许战斗规则直接调用平台 SDK；微信插件和广告桥接停止排期。
- 核心对局不依赖持续联网或运行时下载核心代码；其他技术能力按实际需求评估。
- 不把AppID、密钥、导出凭据或用户数据提交到版本库。
